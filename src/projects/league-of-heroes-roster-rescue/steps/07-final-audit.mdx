# Chapter 7 - Final Roster Audit

The League director has one final request.

This sentence has never improved anyone's afternoon.

The press team is almost ready. The fog machine has been tested. The podium has been polished. Someone has taped a sign over the breakroom microwave that says, "Do not heat fish during hero announcements."

All that remains is the final roster audit.

At the beginning of this project, the League needed a report like this:

```txt
League of Heroes Roster Audit

Heroes on roster: 4
Average power level: 63.25
First responder: Scuba Driver
Newest recruit: Neon Volt
Audit status: Ready for review
```

At the time, the League did not have reliable data underneath that report.

Now it does.

<Callout type="note" title="No new JavaScript tricks">
  You have already used every tool you need for this chapter.

  The final audit is about combining the data you built, updated, organized, inspected, and cleaned throughout the project.
</Callout>

## Clear Out the Old Checks

Before you build the final audit, delete the temporary `console.log()` calls you made for Chapter 6.

You already used them to prove that the roster is in good shape. The final audit should be easy for the League director to read without making them scroll through every diagnostic check you have ever performed.

Keep your `roster` array and hero objects. Keep the imported-value work if you want to refer back to it. Just clean up the console logs that are no longer part of the final report.

## Prepare the Audit Values

The final audit needs five pieces of information:

- the number of heroes on the roster
- the average power level
- the first responder
- the newest recruit
- the audit status

Create a variable for each value before you build the final report.

### Heroes on Roster

Use the `roster` array to create a variable called `heroCount`.

It should store the number of hero objects in the array.

```txt
4
```

### Average Power Level

Create a variable called `totalPowerLevel`.

Add together the power levels of all four heroes currently in the roster.

Then create a variable called `averagePowerLevel`.

Use `totalPowerLevel` and `heroCount` to calculate the average.

Your console should show:

```txt
63.25
```

<Callout type="tip" title="Use the data, not the answer">
  Do not write `63.25` directly into `averagePowerLevel`.

  The average should come from the actual power levels in your roster. That way, the report would still update if one of the hero records changed later.
</Callout>

### First Responder

The first hero in the roster is the current first responder.

Create a variable called `firstResponder` that stores that hero's name.

Your console should show:

```txt
Scuba Driver
```

### Newest Recruit

Neon Volt was the most recently added permanent member of the roster.

Create a variable called `newestRecruit` that stores the name of the last hero in the roster.

Use `.length - 1` instead of a direct index.

Your console should show:

```txt
Neon Volt
```

<PracticeCard
  prompt="Why is `roster[roster.length - 1]` a better choice than `roster[3]` for the newest recruit?"
  answer="It always gets the last hero in the array, even if the roster gains or loses members later."
/>

### Audit Status

Create a variable called `auditStatus`.

Set it to:

```txt
Ready for review
```

The roster is organized, the data is cleaned, and you have checked the important values. The League may proceed with its extremely normal and definitely fish-free press event.

## Build the Final Report

Now use one template literal to log the final roster audit.

Your report should use the variables you created above. Do not type hero names, counts, or the average directly into the template literal.

Your console should show exactly:

```txt
League of Heroes Roster Audit

Heroes on roster: 4
Average power level: 63.25
First responder: Scuba Driver
Newest recruit: Neon Volt
Audit status: Ready for review
```

<details>
<summary>Template-literal reminder</summary>

A template literal uses backticks:

```js
console.log(`Your text goes here`);
```

To place a variable's value inside the text, use `${}`:

```js
console.log(`Heroes on roster: ${heroCount}`);
```

</details>

## Test the Audit

Before you call it finished, make one small temporary change to the roster.

You could:

- increase one hero's `powerLevel`
- add another hero to the end of the roster
- remove the last hero
- move a hero to the front

Then run the final audit again.

Notice which parts of the report change automatically.

When you are finished testing, undo the temporary change so your final output matches the checkpoint.

<Callout type="note" title="This is why data structures matter">
  The report does not need to know every hero's name and power level in advance.

  It gets its information from the `roster` array. That is the point of keeping related information organized in objects, then keeping those objects together in an array.
</Callout>

## Final Checkpoint

Your final console output should be:

```txt
League of Heroes Roster Audit

Heroes on roster: 4
Average power level: 63.25
First responder: Scuba Driver
Newest recruit: Neon Volt
Audit status: Ready for review
```

You are finished when:

- `roster` contains the four correct hero records
- the roster order is Scuba Driver, Solar Flare, Echo Fang, then Neon Volt
- `heroCount` comes from `roster.length`
- `averagePowerLevel` comes from the actual roster data
- `firstResponder` comes from the first hero in `roster`
- `newestRecruit` comes from the last hero in `roster`
- the final report uses a template literal
- the important values are not hardcoded into the report

  The League of Heroes has its roster back.

  Free-Lancer may now enjoy the benefits package, which is mostly capes and a surprisingly complicated dental plan.
</Callout>
