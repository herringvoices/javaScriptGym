# Chapter 7 - Final Roster Audit

The League director has one final request.

This sentence has never improved anyone's afternoon.

The press team is almost ready. The fog machine has been tested. The podium has been polished. Someone has taped a sign over the breakroom microwave that says, "Do not heat fish during hero announcements."

All that remains is the final roster audit.

In this chapter, you will inspect a damaged final roster, repair several planted data issues, and produce one final confirmation that the League can safely proceed with the press event.

No brand-new tricks this time.

This is the chapter where you use the tools you have already practiced:

- object access
- object updates
- array indexes
- array methods
- string cleanup
- number conversion
- careful console checks

In other words: programming, but with a clipboard.

## Learning Goal

By the end of this chapter, you will be able to audit an array of objects against written requirements and repair issues involving property names, value types, missing records, order, and inconsistent text.

## Why This Matters

In real applications, data problems rarely arrive wearing a little name tag that says, "Hello, I am the bug."

They hide inside records.

One property name is slightly wrong. One number is stored as text. One record is missing. One item is in the wrong position. One value has inconsistent capitalization. One team assignment is outdated.

Any one of those might be small.

Together, they make data harder to trust.

A final audit is where you slow down, compare the data to the requirements, and prove that the collection is ready for use.

The League calls this "quality assurance."

The director calls it "please do not let the podium explode."

Both are fair.

## What to Watch For

The damaged final roster includes several problems you have already practiced fixing:

- one hero is missing
- the roster starts in the wrong order
- one property name has the wrong capitalization
- one number is stored as text
- one hero name has messy spacing and capitalization
- one team assignment is outdated

Use the requirements to decide what needs to change.

Do not guess. Audit.

Very glamorous. Extremely clipboard-forward.

## Success Criteria

You are finished when:

- `finalAuditRoster` contains exactly five hero objects
- the heroes are in the required final order
- Star Sentinel has been added
- Echo Nova's name is cleaned
- Echo Nova's team is corrected
- every hero uses `powerLevel` with the same capitalization
- every `powerLevel` value is a number
- every hero object uses the same property naming pattern
- you used string cleanup where text was messy
- you used number conversion where a number was stored as text
- you used array methods for roster-level changes
- the final audit output matches the checkpoint exactly
- your final comment block explains your work clearly

If the roster is almost correct, the roster is not correct. This is the final press version, not a casserole recipe where "close enough" still tastes fine.
