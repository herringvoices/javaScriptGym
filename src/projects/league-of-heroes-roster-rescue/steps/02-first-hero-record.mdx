# Chapter 2 - Create the First Hero Record

In Chapter 1, you created separate variables for The Scuba Driver's information.

That worked. JavaScript now knows his name, power level, city, secret identity situation, and deeply confusing power.

But the League has a problem.

A hero profile is not really seven unrelated facts. They all belong to one hero.

The League's old database kept each hero's information together in one self-contained record. You remember the tool JavaScript gives you for exactly that job:

**objects.**

<Callout type="note" title="Why objects?">
  Objects group related information together using named properties.

  The Scuba Driver's name, power level, home city, and active status all describe the same hero, so they belong in the same object.
</Callout>

## Your Task

Create a variable called `scubaDriver`.

Assign it an object that contains the same information you created in Chapter 1.

Use these property names exactly:

| Property | What it should store |
| --- | --- |
| `heroName` | The Scuba Driver's hero name |
| `isActive` | whether he is currently active |
| `powerLevel` | his current power level |
| `age` | his age |
| `power` | his primary power |
| `secretIdentity` | his secret identity, if he has one |
| `city` | the city he is based in |

## Read from the Record

Your `profileMessage` still uses the separate Chapter 1 variables.

Change the template literal so it uses the object properties instead:

- `scubaDriver.heroName`
- `scubaDriver.power`
- `scubaDriver.powerLevel`

Keep `profileMessage` and `console.log(profileMessage)` exactly where they are for now. Then run your code.

<HandbookChallenge
  title="Try It Before You Fix It"
  hints={[
    "Only replace the values inside the existing template literal.",
    "Do not move any code yet.",
    "Run the file after you make the replacements."
  ]}
>
  Update `profileMessage` to use `scubaDriver` properties, leave it in its Chapter 1 location, and run the code.
</HandbookChallenge>

You should see an error that starts something like this:

```txt
ReferenceError: Cannot access 'scubaDriver' before initialization
```

Why is JavaScript trying to use `scubaDriver` before it knows what `scubaDriver` is?

What can you change so the object exists before `profileMessage` tries to read from it?

Figure it out. Go back to the handbook if you need to.

<details>
<summary>Reveal the fix</summary>

JavaScript runs your file from top to bottom.

`profileMessage` is still above the new `scubaDriver` object, so JavaScript reaches `scubaDriver.heroName` before the object has been created.

Move both `profileMessage` and `console.log(profileMessage)` below the `scubaDriver` object. Then run the code again.

</details>

Your console should show:

```txt
The Scuba Driver has the power of Underwater Transportation with a power level of 5.
```

<PracticeCard
  prompt="Why did moving `profileMessage` below `scubaDriver` fix the error?"
  answer="JavaScript runs the file from top to bottom. The object has to be created before code can read its properties."
/>

<Callout type="warn" title="Do not confuse property names with variable names">
  `scubaDriver.powerLevel` means “get the value stored in the `powerLevel` property on the `scubaDriver` object.”

  `powerLevel` by itself still refers to your separate Chapter 1 variable. JavaScript will not assume you meant the object. It has boundaries.
</Callout>
