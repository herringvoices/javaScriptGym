# Chapter 6 - Inspect the League's Data

The League roster is updated.

Nobody has screamed.

The spreadsheet printer is quiet.

These are all encouraging signs.

But before the League uses this roster to create its audit report, they want one more thing: evidence.

Not vibes. Not “I think it works.” Not “the data looked fine when I glanced at it while eating crackers.”

Evidence.

In this chapter, you will inspect the roster directly, use object utilities to look inside hero records, and clean up a few values imported from another system.

<Callout type="note" title="What you are practicing">
  The roster already exists. You are not rebuilding it in this chapter.

  You are proving that you can inspect the data inside it, clean text, convert imported values into usable numbers, and access information from the beginning, middle, and end of an array.
</Callout>

## Start a League Data Check

At the bottom of your `main.js` file, create a new section for this chapter.

Start by logging a heading:

```js
console.log("League Data Check");
```

Then log the number of heroes currently in the roster.

Your console should begin like this:

```txt
League Data Check
4
```

## Inspect One Hero Record

The League wants to make sure every hero record still has the expected structure.

Use `Object.keys()` with Scuba Driver's object to inspect the property names in the first roster record.

Your console should show:

```txt
id,heroName,isActive,powerLevel,age,power,secretIdentity,city
```

Then use `Object.values()` with the same hero record.

Your console should show:

```txt
1,Scuba Driver,true,10,21,Underwater Transportation,,Old York
```

That empty space between the commas represents Scuba Driver's `null` secret identity. It is still there. It is just not much of a conversationalist.

<HandbookChallenge
  title="Inspect the First Record"
  hints={[
    "Scuba Driver is still the first hero in `roster`.",
    "`Object.keys()` gives you an array of property names.",
    "`Object.values()` gives you an array of the values stored in those properties."
  ]}
>
  Log Scuba Driver's property names and values using object utilities.
</HandbookChallenge>

<Callout type="tip" title="A consistent shape is useful">
  Every hero record should use the same property names.

  That way, future code can ask any hero for `heroName`, `powerLevel`, or `city` without needing a separate set of instructions for every person in the roster.
</Callout>

## Inspect a Property and Its Value

The League also wants proof that you can inspect a property/value pair.

Use `Object.entries()` with Scuba Driver's object.

Then log the first entry from the result.

Your console should show:

```txt
id,1
```

<details>
<summary>What is happening here?</summary>

`Object.entries(roster[0])` creates an array of smaller arrays.

The first one looks like this:

```js
["id", 1]
```

When JavaScript logs that array, it displays:

```txt
id,1
```

</details>

<PracticeCard
  prompt="Which expression gets the first property/value pair from Scuba Driver's object?"
  answer="`Object.entries(roster[0])[0]`"
 />

<HandbookChallenge

</Callout>

## Clean Imported Text

The League has also recovered a few values from Dr. Breach's extremely questionable backup system.

Add these variables below your roster work:

```js
const importedCodename = "  neon-volt  ";
const importedPowerLevel = "21 points";
const importedBadgeScore = "91.5";
```

The press team needs the codename to display like this:

```txt
NEON VOLT
```

Create a new variable called `cleanCodename`.

Use string methods to:

1. remove the extra spaces
2. replace the dash with a space
3. convert the result to uppercase

Then log `cleanCodename`.

## Parse Imported Numbers

The imported power level looks like a number, but JavaScript still sees it as text.

Create a variable called `parsedPowerLevel` that uses `parseInt()` to turn the imported power level into a usable number.

Then log:

1. `parsedPowerLevel`
2. `typeof parsedPowerLevel`

Your console should show:

```txt
21
number
```

Next, create a variable called `parsedBadgeScore` that uses `parseFloat()` to turn the badge score into a number without losing its decimal.

Your console should show:

```txt
91.5
```

<HandbookChallenge
  title="Parse the Imports"
  hints={[
    "`parseInt()` is useful when you need a whole number from text.",
    "`parseFloat()` is useful when the number may include a decimal.",
    "Log the type after parsing the power level. The value can look correct while still being a string."
  ]}
>
  Parse the imported power level and badge score, then log the requested evidence.
</HandbookChallenge>

<Callout type="note" title="Looks can be deceiving">
  `"21"` and `21` look almost identical when they print to the console.

  They are not the same type. A string is text. A number can participate in numeric calculations and comparisons.
</Callout>
