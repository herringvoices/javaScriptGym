# Chapter 6 - Inspect the League's Data

The League roster is updated.

Nobody has screamed.

The spreadsheet printer is quiet.

These are all encouraging signs.

But before the League sends this roster to the press team, they want one more thing: evidence.

Not vibes. Not "I think it works." Not "the data looked fine when I glanced at it while eating crackers."

Evidence.

In this chapter, you will use basic JavaScript properties and methods to inspect the roster, clean imported text, parse imported numbers, and prove that the data is ready to use.

## Learning Goal

By the end of this chapter, you will be able to use basic JavaScript properties and methods to inspect, clean, parse, and verify data in objects and arrays.

## Why This Matters

Real data work is not only creating and changing records.

A lot of the job is checking what you actually have.

Before a website displays account information, submits an order, filters a product list, or sends a report, the code needs to know that the data is in the shape it expects.

Is the array the right length?

Does this object have the properties we expect?

Is this imported number actually a number?

Does this imported text need extra spaces removed?

Can we compare a numeric value after parsing it?

These are small checks, but they prevent bigger headaches later.

The League calls this a **data check** because "please make sure the roster is not secretly nonsense" did not fit on the form.

## Methods and Properties You May Need

For this chapter, keep the work direct and inspectable.

You may need:

- `.length`
- `.trim()`
- `.replace()`
- `.split()`
- `.toUpperCase()`
- `parseInt()`
- `parseFloat()`
- `Object.keys()`
- `Object.values()`
- `Object.entries()`
- direct access through objects and arrays
- a comparison that produces a boolean

If those feel rusty, review the handbook chapters for [string methods](/handbook/JS.VDT.MTH/JS.VDT.MTH.STR), [number parsing](/handbook/JS.VDT.MTH/JS.VDT.MTH.NUM_PARSE), [object utilities](/handbook/JS.VDT.MTH/JS.VDT.MTH.OBJ_UTIL), and [array end controls](/handbook/JS.VDT.MTH/JS.VDT.COL.ARR_ENDS).

Do not use loops or higher-order array methods for this chapter. Those are useful tools, but this checkpoint is about direct inspection.

## Imported Cleanup Values

Find these imported values in `main.js` after your Chapter 5 change requests:

```js
const importedCodename = "  star-sentinel  ";
const importedPowerLevel = "88 points";
const importedBadgeScore = "91.5";
```

These represent data that came in from another system.

The codename has messy spacing and a dash.

The press badge system wants codenames in all caps.

The power level includes extra text after the number.

The badge score includes a decimal.

Your job is to clean and parse them before logging your evidence.

## Your Task

Create a **League Data Check** section in `main.js`.

Your data check should prove:

- the roster contains the expected number of heroes
- one hero record has the expected property names
- one object utility can show the values from a hero record
- one object utility can show property/value pairs from a hero record
- the first, middle, and last heroes can be accessed by position
- the last hero can be accessed with `.length - 1`
- the imported codename can be cleaned into display-ready text
- the imported power level can be parsed into a number
- the imported badge score can be parsed without losing its decimal
- a parsed number can be used in a comparison
- a specific hero has the expected team assignment after the Chapter 5 updates

- One `Quantum Quill` line should come from direct index access.

- The parsed power level should display as `88`.

- The final sentence should use the updated Neon Volt team assignment from Chapter 5.

## Success Criteria

You are ready for Chapter 7 when:

- your data check starts with `League Data Check`
- the roster count is `5`
- your property-name check confirms the expected hero object shape
- your object values check shows Crimson Phoenix's values
- your object entries check proves you can inspect a property/value pair
- your position checks show Crimson Phoenix, Star Sentinel, and Quantum Quill
- your final-position check uses `.length - 1`
- your cleaned codename displays as `STAR SENTINEL`
- your parsed power level behaves like a number
- your parsed decimal keeps the decimal value
- your comparison produces `true`
- your final team-assignment sentence confirms Neon Volt is assigned to Vanguard
- you used direct object and array access, not loops or higher-order array methods

If your imported power level logs as `88` but its type is still `string`, JavaScript is politely holding up a tiny sign that says, "Looks can be deceiving."
