# Chapter 6 - Inspect the League's Data

The League roster is updated. Nobody has screamed. The spreadsheet printer is quiet.

These are all encouraging signs.

Before the League creates its audit report, it wants evidence. Not vibes. Not “I think it works.” Evidence.

In this chapter, you will inspect the roster directly, use object utilities to look inside hero records, and clean up values imported from another system.

<Callout type="note" title="What you are practicing">
  The roster already exists. You are not rebuilding it in this chapter.

  You are inspecting its data, cleaning text, converting imported values into usable numbers, and accessing information from the beginning, middle, and end of an array.
</Callout>

At the bottom of `main.js`, create a new section and log a heading:

console.log("League Data Check");

## Inspect One Hero Record

Use `Object.keys()` with Scuba Driver's object to inspect the property names in the first roster record.

```txt
id,heroName,isActive,powerLevel,age,power,secretIdentity,city
```

Then use `Object.values()` with the same record.

```txt
1,Scuba Driver,true,10,21,Underwater Transportation,,Old York
```

That blank space between the commas represents Scuba Driver's `null` secret identity. It is still there. It is just not much of a conversationalist.

<HandbookChallenge
  title="Inspect the first hero record"
  hints={[
    <>Scuba Driver is the first object in <code>roster</code>.</>,
    <><code>Object.keys()</code> returns an array of property names; <code>Object.values()</code> returns the corresponding values.</>,
    <>Pass the hero object itself into each utility.</>,
  ]}
  expected={
    <pre className="m-0 whitespace-pre-wrap">{`id,heroName,isActive,powerLevel,age,power,secretIdentity,city
1,Scuba Driver,true,10,21,Underwater Transportation,,Old York`}</pre>
  }
  solution={
    <pre className="m-0 whitespace-pre-wrap">{`console.log(Object.keys(roster[0]));
console.log(Object.values(roster[0]));`}</pre>
  }
>
  <p className="m-0">
    Use object utilities on <code>roster[0]</code> to log its property names and then its stored values. Confirm that the record still has the consistent hero shape and Scuba Driver’s updated data.
  </p>
</HandbookChallenge>

<Callout type="tip" title="A consistent shape is useful">
  Every hero record should use the same property names. That way, future code can ask any hero for `heroName`, `powerLevel`, or `city`.
</Callout>

## Inspect a Property and Its Value

Use `Object.entries()` with Scuba Driver's object, then log the first entry from the result.

```txt
id,1
```

<details>
<summary>What is happening here?</summary>

`Object.entries(roster[0])` creates an array of smaller arrays. The first one is:

```js
["id", 1]
```

When JavaScript logs that array, it displays `id,1`.

</details>

<PracticeCard
  prompt="Which expression gets the first property/value pair from Scuba Driver's object?"
  answer="`Object.entries(roster[0])[0]`"

## Clean Imported Text

The League recovered a few values from Dr. Breach's extremely questionable backup system.

```js
const importedCodename = "  neon-volt  ";
const importedPowerLevel = "21 points";
const importedBadgeScore = "91.5";
```

The press team needs this codename:

```txt
NEON VOLT
```

<HandbookChallenge
  title="Clean the imported codename"
  hints={[
    <>Remove the outside whitespace before changing the text’s internal punctuation.</>,
    <>Replace the dash with a normal space.</>,
    <>Apply the case conversion to the cleaned result.</>,
  ]}
  expected={
    <pre className="m-0 whitespace-pre-wrap">{`NEON VOLT`}</pre>
  }
  solution={
    <pre className="m-0 whitespace-pre-wrap">{`const importedCodename = "  neon-volt  ";
const cleanCodename = importedCodename
  .trim()
  .replace("-", " ")
  .toUpperCase();

console.log(cleanCodename);`}</pre>
  }
>
  <p className="m-0">
    Create <code>cleanCodename</code> from <code>importedCodename</code> by removing the extra outside spaces, replacing the dash with a space, and converting the final text to uppercase. Log the cleaned value.
  </p>
</HandbookChallenge>

## Parse Imported Numbers

The imported power level looks like a number, but JavaScript still sees it as text.

<HandbookChallenge
  title="Parse the imported numeric values"
  hints={[
    <><code>parseInt()</code> can read the whole-number prefix from text such as <code>"21 points"</code>.</>,
    <><code>parseFloat()</code> keeps the decimal portion of a numeric string.</>,
    <>Store the parsed values so later comparisons use numbers rather than the original strings.</>,
  ]}
  expected={
    <pre className="m-0 whitespace-pre-wrap">{`21
91.5`}</pre>
  }
  solution={
    <pre className="m-0 whitespace-pre-wrap">{`const importedPowerLevel = "21 points";
const importedBadgeScore = "91.5";

const parsedPowerLevel = parseInt(importedPowerLevel);
const parsedBadgeScore = parseFloat(importedBadgeScore);

console.log(parsedPowerLevel);
console.log(parsedBadgeScore);`}</pre>
  }
>
  <p className="m-0">
    Convert <code>importedPowerLevel</code> into a whole number named <code>parsedPowerLevel</code> and <code>importedBadgeScore</code> into a decimal number named <code>parsedBadgeScore</code>. Log both parsed values.
  </p>
</HandbookChallenge>

<Callout type="note" title="Looks can be deceiving">
  `"21"` and `21` look almost identical when they print to the console. A string is text; a number can participate in numeric calculations and comparisons.
</Callout>
