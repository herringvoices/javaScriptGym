# Chapter 4 - Assemble the Roster

Scuba Driver's record is organized. It is current. It is beautiful.

It is also one hero.

The League of Heroes has checked the rulebook and confirmed that one hero does not, in fact, make a League.

To build a roster, the League needs an ordered collection of hero records.

You know what JavaScript uses for ordered collections:

**arrays.**

<Callout type="note" title="The roster plan">
  Each hero will be an object.

  The `roster` will be an array that stores those hero objects in order.
</Callout>

## Clean Up Your Console

Before you begin, delete the profile sentence and data-scan `console.log()` calls from the earlier chapters.

You already used those to confirm that Scuba Driver's data was correct. Keeping every old test forever would make your console harder to read than it needs to be.

You can also update the `scubaDriver` object directly now. You have already practiced using assignment operators in Chapter 3.

## Give Scuba Driver an ID

Before Scuba Driver joins the roster, add an `id` property to the `scubaDriver` object.

Set the value to `1`.

```txt
ID: 1
```

<Callout type="tip" title="An ID is not an array index">
  An ID identifies a particular hero record.

  An array index identifies a record's current position in the roster.

  Scuba Driver can have an ID of `1` while living at index `0`. JavaScript is not being difficult. Those numbers answer different questions.
</Callout>

## Create the Roster

Create an array called `roster` directly above your `console.log()` calls.

Put the `scubaDriver` object inside it.

```txt
roster
└── scubaDriver
```

Then update your console message so it gets its information from the array instead of directly from `scubaDriver`.

Your console should show:

```txt
Hero number 1 is Scuba Driver.
```

Remember: arrays are zero-indexed.

## Add Two More Heroes

The League has sent you information on two more heroes.

Create an object for each hero, then add both objects directly inside the `roster` array declaration.

Every hero record should use the same properties as Scuba Driver's record:

- `id`
- `heroName`
- `isActive`
- `powerLevel`
- `age`
- `power`
- `secretIdentity`
- `city`

### Hero Profile: Solar Flare

```txt
ID: 2
Hero name: Solar Flare
Active: true
Power level: 18
Age: 34
Power: Heat and Light Control
Secret identity: Cameron Vale
City: Old York
```

### Hero Profile: Echo Fang

```txt

```

<Callout type="warn" title="Consistency matters">
  Do not give one hero a `name` property and another hero a `heroName` property.

  Do not give one hero a `location` property and another hero a `city` property.

  A roster works best when every record follows the same structure. Future code should be able to ask any hero for `heroName` without first checking what that hero decided to call it.
</Callout>

## Read from the Roster

Now create a console message for each hero.

Use the array to get the correct hero, then use the object's properties to build the message.

Your console should show:

```txt
Hero number 1 is Scuba Driver.
Hero number 2 is Solar Flare.
Hero number 3 is Echo Fang.
```

For the second and third heroes, use bracket notation to access the correct item in the array.

<details>
<summary>What bracket notation means here</summary>

`roster[1]` gets the second hero object.

`roster[2]` gets the third hero object.

From there, you can use dot notation to access a property:

```js
roster[1].heroName
```

That means:

> Get the second object from `roster`, then get that object's `heroName`.

</details>

## Checkpoint

Before you move on, your roster should contain three hero objects.

Your console should show:

```txt
Hero number 1 is Scuba Driver.
Hero number 2 is Solar Flare.
Hero number 3 is Echo Fang.
```

You should also be able to log these values:

```txt
1
Old York
2
Solar Flare
3
Sound Tracking
```

Those values come from:

```js
console.log(roster[0].id);
console.log(roster[0].city);
console.log(roster[1].id);
console.log(roster[1].heroName);
console.log(roster[2].id);
console.log(roster[2].power);
```
