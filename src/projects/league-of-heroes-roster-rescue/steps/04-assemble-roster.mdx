# Chapter 4 - Assemble the League Roster

Excellent news: the League now has two usable hero records.

Less excellent news: two heroes do not make a roster. That is just a buddy system with branding.

The press event needs an official public lineup. The League director does not want "a few hero objects floating around somewhere in the file." The director wants one ordered collection that represents the active roster.

That is what an **array** is for.

An array lets you store multiple related values in one ordered list. In this case, each value in the list will be a hero object.

Welcome to the dramatic and extremely administrative world of **arrays of objects**.

## Learning Goal

By the end of this chapter, you will be able to organize multiple related objects into an array, access records by index, and use `.length` to inspect the collection.

## Why This Matters

In Chapter 3, you saw why matching object shapes matter.

Now imagine a website that needs to display every active hero on a roster page.

If each hero is trapped in a separate variable, the page has no single collection to work with. The code would need to know every individual variable name ahead of time, which is not realistic once the League grows.

A roster array solves that problem.

Instead of thinking:

```txt
Here is one hero.
Here is another hero.
Here is another hero.
Please remember all of them individually forever.
```

You can think:

```txt
Here is the League roster.
It contains the hero records in public lineup order.
```

That is much easier for future code to use.

## Public Lineup Order

The order matters.

Arrays use positions called **indexes**. The first item is at index `0`, the second item is at index `1`, and so on.

That means the League's public lineup should work like this:

```txt
Index 0: Crimson Phoenix
Index 1: Neon Volt
Index 2: Star Sentinel
Index 3: Echo Eclipse
```

This is one of those JavaScript things that feels suspicious at first. The first item being index `0` is not a typo. It is tradition. Ancient, weird tradition.

## Use Length Like a Developer

The roster should have four heroes.

The last hero is not at index `4`. The last hero is at index `3`.

Why? Because the first hero is at index `0`.

When you need the last item in an array, use the array's `.length` property to help:

```txt
last index = array length - 1
```

That pattern matters because real arrays change size. Hard-coding the last index works only until the roster changes, which it will, because the League director has access to email.
