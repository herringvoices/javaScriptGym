# Chapter 8 - Respond to a New Breach

The press event was a success.

The fog machine behaved itself. Nobody heated fish. Scuba Driver gave a short speech that was mostly about the importance of accessible public pools.

The League's roster audit worked.

Then Dr. Breach sent one final message:

> “Nice spreadsheet. Shame if something happened to it.”

He did not attach a virus.

He attached a **change request**.

<Callout type="danger" title="One last job">
  You have completed the guided repair work.

  This chapter gives you a new situation and the requirements for a solution. It does not tell you exactly which method or expression to use for every step.

  That is intentional. You already know the tools.
</Callout>

## The Situation

The League is sending a small emergency response team to investigate a suspicious breach at the Museum of Extremely Normal Artifacts.

They need a new array called `emergencyRoster`.

Create a new array using hero objects already inside `roster`. Do **not** remove heroes from the main roster.

The emergency roster begins with these heroes in this order:

```txt
1. Solar Flare
2. Neon Volt
```

<Callout type="warn" title="A new array, not a second League">
  `emergencyRoster` is a separate array, but it can contain references to hero objects from `roster`.

  You are creating a new list for one mission. You are not recreating every hero record or removing anyone from the League's main roster.
</Callout>

## Emergency Update 3: Clean the Dispatch Message

The museum's automated dispatch system sends this message:

```js
const importedMuseumMessage = "  breach detected: gallery-7  ";
```

The League needs it displayed like this:

```txt
BREACH DETECTED: GALLERY 7
```

<HandbookChallenge
  title="Clean the museum dispatch message"
  hints={[
    <>Start by removing only the unwanted whitespace at the beginning and end.</>,
    <>Replace the dash with a normal space before formatting the final text.</>,
    <>Apply uppercase conversion after the message has been cleaned.</>,
  ]}
  expected={
    <pre className="m-0 whitespace-pre-wrap">{`BREACH DETECTED: GALLERY 7`}</pre>
  }
  solution={
    <pre className="m-0 whitespace-pre-wrap">{`const importedMuseumMessage = "  breach detected: gallery-7  ";
const cleanMuseumMessage = importedMuseumMessage
  .trim()
  .replace("-", " ")
  .toUpperCase();

console.log(cleanMuseumMessage);`}</pre>
  }
>
  <p className="m-0">
    Create <code>cleanMuseumMessage</code> from <code>importedMuseumMessage</code>. Remove the outside spaces, replace the dash with a space, convert the result to uppercase, and log the cleaned message.
  </p>
</HandbookChallenge>

## Emergency Update 4: Parse the Threat Level

The museum also sends this value:

```js
const importedThreatLevel = "73%";
```

Create a variable called `threatLevel`.

Convert the imported value into a number, then log:

1. the parsed threat level
2. its type
3. whether it is greater than Solar Flare's power level

Your console should show:

```txt
73
number
true
```

<Callout type="note" title="Data from outside your program needs checking">
  Your code did not create the imported threat level, so it cannot assume the value is already the type it needs.

  That is why parsing matters. Other systems are frequently weird in ways that feel personal.
</Callout>

## Create the Emergency Dispatch Report

Now create one final report for the emergency response team.

Use values from your `emergencyRoster`, `cleanMuseumMessage`, and `threatLevel`.

Your report should show:

```txt
Emergency Dispatch Report

Alert: BREACH DETECTED: GALLERY 7
Threat level: 73
Lead responder: Scuba Driver
Support team size: 3
Last assigned hero: Echo Fang
```

A few notes:

- The lead responder is the first hero in `emergencyRoster`.
- The last assigned hero is the last hero in `emergencyRoster`.
- The support team size is everyone **except** the lead responder.
- Do not hardcode the names or numbers into the report.
