# Chapter 1 - Open the Case File

Bad news: the League of Heroes has been hit by a data breach.

Worse news: the villain responsible calls themselves **The CSV**, which is somehow both deeply boring and immediately suspicious.

Their attack left the League's roster incomplete, inconsistent, and just embarrassing enough that nobody wants it shown at the annual **Definitely Not a Parade of Dangerous People** press event.

That is where you come in.

Before you repair hero records, you need to open the case file. The case file starts with small pieces of information: names, counts, yes/no settings, and values that are not known yet.

That means this chapter is about **primitive values**.

## Learning Goal

By the end of this chapter, you will be able to choose useful primitive value types, decide when to use `const` or `let`, and combine those values in a readable status message.

## Your Task

In `main.js`, create variables for the League's case file.

You need:

- `leagueName` - the public name of the organization
- `activeHeroCount` - the current number of active heroes
- `emergencyRosterEnabled` - whether the emergency roster is turned on
- `missingCoordinator` - the name of the missing roster coordinator
- `meetingLocation` - the currently unknown meeting location
- `backupMeetingLocation` - a location the League chooses after the file opens

Choose a value type that fits each piece of information.

Use `const` for values that should not change during this chapter.

Use `let` for a value that starts unknown and gets updated later.

## Client Note

The League sent this intake note:

```txt
Organization: League of Heroes
Active heroes: 7
Emergency roster: enabled
Missing coordinator: Dana Cipher
Meeting location: unknown
Backup meeting location selected later: Rooftop Annex
```

Turn that note into JavaScript variables.

The meeting location is intentionally unknown at first. That is a good use for `null`.

After your starter variables exist, update the meeting location to use the backup meeting location. This is the one value in the chapter that should be reassigned.

## Watch the Types

The League's forms are dramatic, but JavaScript is picky in a quieter way.

- Names and locations should be strings.
- Counts should be numbers.
- Enabled/disabled settings should be booleans.
- Intentionally unknown information should start as `null`.

Do not store the active hero count as `"7"`. That is text wearing a number costume.

Do not store the emergency roster as `"enabled"`. Your future code wants a real yes/no value.

## Checkpoint

Create console logs that prove your case file is holding the right values.

Your console should show these exact values:

```txt
League of Heroes
7
true
Dana Cipher
null
Rooftop Annex
```

Then create one readable status message using the variables.

Your console should show this exact sentence:

```txt
League of Heroes has 7 active heroes. Emergency roster enabled: true. Dana Cipher is missing.
```

Finally, log the meeting location after you update it.

Your console should show:

```txt
Meeting location confirmed: Rooftop Annex
```

## Success Criteria

You are ready for Chapter 2 when:

- `leagueName` is a string
- `activeHeroCount` is a number
- `emergencyRosterEnabled` is a boolean
- `missingCoordinator` is a string
- `meetingLocation` starts as `null`
- `meetingLocation` is later reassigned to the backup location
- you used `const` for values that stay the same
- you used `let` for the value that changes
- your console output matches the checkpoint

If your console says `undefined has undefined active heroes`, congratulations: JavaScript has entered the room and immediately started taking attendance. Check your variable names carefully.
