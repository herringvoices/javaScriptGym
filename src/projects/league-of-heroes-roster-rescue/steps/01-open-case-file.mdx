# Chapter 1 - Open the Case File

You've learned a lot in your JavaScript journey.

- [ ] You can **declare, assign, and update variables** using `let` and `const`
- [ ] You can **store and choose appropriate primitive values**, including strings, numbers, booleans, `null`, and `undefined`
- [ ] You can **combine, calculate, and compare values** using operators, expressions, and template literals
- [ ] You can **create and use objects** to group related data with key-value pairs
- [ ] You can **create and use arrays** to store ordered lists of values
- [ ] You can **work with arrays of objects** to represent structured records like books, users, or API results
- [ ] You can **access and update data** using dot notation, bracket notation, indexes, and nested paths
- [ ] You can **add, remove, and reorder array items** with methods like `.push()`, `.pop()`, `.shift()`, and `.unshift()`
- [ ] You can **use common properties and methods** to inspect, clean, format, convert, and reshape strings, numbers, arrays, and objects
- [ ] You can **choose an appropriate data type or data structure** for the kind of information your program needs

Once you wrote it all out, you started to feel pretty proud of yourself and promptly signed up for the **League of Heroes** superhero team.

Unsurprisingly, they let you join immediately and gave you the hero name **Free-Lancer**. You asked about getting a lance, but they said they wanted the emphasis to be on the "free" part.

And you couldn't have come at a better time. The dreaded **Dr. Breach** has completely wrecked the League's roster data.

The League still has an audit report it needs before it can send heroes out on missions. Right now, though, the report is about as useful as a Bat-Signal in broad daylight.

```txt
League of Heroes Roster Audit

Heroes on roster: 4
Average power level: 63
First responder: Scuba Driver
Newest recruit: Neon Volt
Audit status: Ready for review
```

By the end of this project, you will rebuild the League's data until it can produce a report like that using real information from the roster.

<Callout type="note" title="Your mission">
  You have already learned every JavaScript tool you will need for this project.

  This is not about remembering every method perfectly without help. It is about looking at a problem, deciding what kind of data you need, and choosing the right tool to work with it.
</Callout>

Along the way, you'll use `console.log()` to inspect your work and make sure the League's data is actually doing what it is supposed to do.

## Step 1: Primitives

The League has sent you some information on one of their members to get your feet wet:

> His name is The Scuba Driver. He is currently active. His power level is 5. His age is 20. His power is "Underwater Transportation" (whatever that is), and he doesn't have a secret identity. He just *is* Scuba Driver. He's based out of "New Atlantis."

To start, create variables for:

- `name`
- `isActive`
- `powerLevel`
- `age`
- `power`
- `secretIdentity`
- `city`

Think carefully about what data type each variable should contain.

Then use your variables and string interpolation to `console.log()` this sentence with the correct information:

```txt
______ has the power of ______ with a power level of ____.
```

## Run a Data Scan

Now that you have created Scuba Driver's profile, ask JavaScript what data types you chose:

```js
console.log(typeof name);
console.log(typeof age);
console.log(typeof powerLevel);
console.log(typeof isActive);
console.log(typeof power);
console.log(typeof city);
console.log(secretIdentity === null);
```

Do not open the scanner results yet. Run your code first and look at your console.

<PracticeCard
  prompt="Before you run the scan, what do you expect the final line to print?"
  answer="It should print `true`, because `secretIdentity` should be set to `null`."
/>

<details>
<summary>Expected data scan</summary>

```txt
string
number
number
boolean
string
string
true
```

If your last line says `true`, that means `secretIdentity` is correctly set to `null`.

JavaScript quirk: we check `secretIdentity === null` instead of `typeof secretIdentity` because `typeof null` returns `"object"`.

</details>
