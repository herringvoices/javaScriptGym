# Chapter 3 - Update Stale Data

Scuba Driver's profile is finally organized.

Which is when the League realizes the information they sent you was old.

Naturally.

<Callout type="warn" title="Incoming correction">
  The League did not send you bad data on purpose.

  They just apparently update records with the same urgency most people use to update their emergency contacts.
</Callout>

In Chapter 2, you created one `scubaDriver` object. Now you are going to update information inside that existing object.

That matters because real data changes over time. People move. Names change. Stats go up. Sometimes a hero discovers they have been calling themselves **The Scuba Driver** when everyone else has just been calling them **Scuba Driver**.

You do not need to create a brand-new object every time one piece of information changes.

## The Change Request

The League has sent these updates:

```txt
Hero name: Scuba Driver
Age: 21
Power level: 10
City: Old York
```

Everything else in Scuba Driver's profile should stay the same.

## Your Task

Update the existing `scubaDriver` object so its data matches the League's corrections.

Use assignment operators where they make sense:

- Use `=` when replacing a value.
- Use `+=` when increasing a value by a known amount.
- Use `++` when increasing a value by exactly `1`.

<HandbookChallenge
  title="Process the Change Request"
  hints={[
    "Use dot notation to reach the property you want to update.",
    "Scuba Driver's age increases by exactly one year.",
    "His power level increases from 5 to 10. You can replace the value, or add 5 to the existing value."
  ]}
>
  Update Scuba Driver's name, age, power level, and city without creating a new object.
</HandbookChallenge>

<Callout type="note" title="Why update instead of rewriting?">
  In a real application, the original object often comes from a database, an API, or a form submission.

  You would not open the database file and manually rewrite the whole person every time they move. Your application would update the specific data that changed.
</Callout>

## Before and After

Before you make any updates, copy your Chapter 2 profile `console.log()` and run it once.

Then run the same profile message again after your changes.

Your console should show both versions:

```txt
The Scuba Driver has the power of Underwater Transportation with a power level of 5.
Scuba Driver has the power of Underwater Transportation with a power level of 10.
```

Notice what changed:

- The word `"The"` disappeared from the hero name.
- The power level increased.
- The power itself stayed the same.

The League does not need you to announce every field in the object each time. It just needs to know that the updated values actually made it into the record.

## Check the Updated Values

Add console logs for the properties that changed.

Your console should show:

```txt
Scuba Driver
21
10
Old York
```

Then check that the information that did **not** change is still there:

```txt
true
Underwater Transportation
true
```

Those values should represent:

1. whether Scuba Driver is active
2. Scuba Driver's power
3. whether `secretIdentity` is still `null`

<details>
<summary>One possible set of checks</summary>

```js
console.log(scubaDriver.heroName);
console.log(scubaDriver.age);
console.log(scubaDriver.powerLevel);
console.log(scubaDriver.city);

console.log(scubaDriver.isActive);
console.log(scubaDriver.power);
console.log(scubaDriver.secretIdentity === null);
```

</details>

<Callout type="tip" title="Inspect after every change">
  When you update data, log the part you changed.

  A typo like `scubaDriver.powerlevel` does not update `powerLevel`. It creates a new property with a slightly different name. JavaScript will let you do that with the calm confidence of someone handing you the wrong package at the post office.
</Callout>

## Checkpoint

Before you move on, your `scubaDriver` object should contain:

| Property | Expected value |
| --- | --- |
| `heroName` | `"Scuba Driver"` |
| `isActive` | `true` |
| `powerLevel` | `10` |
| `age` | `21` |
| `power` | `"Underwater Transportation"` |
| `secretIdentity` | `null` |
| `city` | `"Old York"` |
