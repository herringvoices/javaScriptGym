# Chapter 5 - Process Roster Changes

The League finally has a roster.

Naturally, this means the roster is already out of date.

Heroes join. Heroes step away. Emergency substitutes appear for reasons nobody fully explains. Sometimes someone gets moved to the front because there is a giant robot downtown and apparently line order matters now.

The good news is that you do not need to rebuild the whole `roster` array every time something changes.

JavaScript gives arrays methods for adding and removing items from either end.

<Callout type="note" title="The roster desk">
  In Chapter 4, you created the starting roster.

  In this chapter, leave that original array declaration alone. Make changes *after* the roster exists so your code tells the story in the same order the League receives the requests.
</Callout>

## Starting Roster

Before you begin, your roster should contain these heroes in this order:

```txt
1. Scuba Driver
2. Solar Flare
3. Echo Fang
```

That means:

```txt
Index 0: Scuba Driver
Index 1: Solar Flare
Index 2: Echo Fang
```

If that is not your current roster, go back and fix Chapter 4 before continuing.

## The Tools You Need

For this chapter, you will use:

- `.push()` to add an item to the end
- `.pop()` to remove an item from the end
- `.unshift()` to add an item to the beginning
- `.shift()` to remove an item from the beginning

<Callout type="tip" title="Read the request before choosing the method">
  Do not start by asking, “Which method have I not used yet?”

  Start by asking, “Where does this hero need to go?” or “Where is this hero being removed from?”
</Callout>

## Request 1: Add a New Recruit

The League has approved a new hero: **Neon Volt**.

Create an object for Neon Volt using the same property names as the heroes already in your roster.

```txt
ID: 4
Hero name: Neon Volt
Active: true
Power level: 21
Age: 26
Power: Electro-kinesis
Secret identity: Maya Chen
City: Metroburg
```

Then add Neon Volt to the **end** of the roster.

## Request 2: Badge Inspection

The League's badge printer needs to inspect Neon Volt's record.

Remove the last hero from the roster and store the removed object in a variable called `badgeCheckHero`.

Then log the removed hero's name.

Your console should show:

```txt
Neon Volt
```

<HandbookChallenge
  title="Send the Badge Record"
  hints={[
    "The hero being removed is at the end of the roster.",
    "One array method removes and returns the last item.",
    "Store that returned object in `badgeCheckHero`."
  ]}
>
  Remove Neon Volt from the end of `roster`, save the removed object, and log their hero name.
</HandbookChallenge>

<Callout type="note" title="Removed does not mean destroyed">
  `.pop()` removes an item from the array, but it also gives that item back to you.

  Saving the result means Neon Volt can return after the badge check instead of vanishing into the administrative void.
</Callout>

## Request 3: Return the Recruit

The badge printer has completed its inspection and confirms that Neon Volt is, in fact, still Neon Volt.

Add `badgeCheckHero` back to the end of the roster.

Then log the roster length.

Your console should show:

```txt
4
```

## Request 4: Emergency Substitute

The League director has decided the roster needs an emergency substitute at the very front.

Create this hero:

```txt

Active: true
Power level: 12
Age: 41
Power: Standing in Line
Secret identity: Temporary Terry
City: Clipboard City
```

Add Placeholder Paladin to the **beginning** of the roster.

## Checkpoint

After all five requests, your roster should be back to four heroes in this order:

```txt
1. Scuba Driver
2. Solar Flare
3. Echo Fang
4. Neon Volt
```

Your console should show:

```txt
4
Scuba Driver
Solar Flare
Echo Fang
Neon Volt
```

One possible set of checks:

```js
console.log(roster.length);
console.log(roster[0].heroName);
console.log(roster[1].heroName);
console.log(roster[2].heroName);
console.log(roster[3].heroName);
```

<Callout type="warn" title="Do not manually rewrite the roster">
  The final roster should be correct because you used array methods to change it.

  Do not go back to the Chapter 4 array declaration and quietly add Neon Volt there. That would make the final output look right, but you would skip the part where the roster actually responds to change.
</Callout>

<Callout type="note" title="The roster can move">

</Callout>
