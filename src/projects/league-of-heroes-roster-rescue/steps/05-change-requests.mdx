# Chapter 5 - Process the Roster Change Requests

The League director has reviewed the public lineup.

Naturally, this means the lineup is no longer correct.

This is normal client behavior. A client will look directly at the thing they approved yesterday and say, "Perfect. Now change it."

The good news: your heroes are already organized in `leagueRoster`.

The better news: arrays come with built-in methods that let you add, remove, and replace items without rebuilding the whole roster from scratch.

Today, you are the roster desk.

Please stamp forms responsibly.

## Learning Goal

By the end of this chapter, you will be able to update an array of objects by adding, removing, replacing, and editing records while keeping the collection in the correct order.

## Why This Matters

Real application data changes constantly.

A user signs up. Another user deletes an account. Someone updates their display name. A product goes out of stock. A support ticket gets reassigned.

If your data lives in an array, you need to know how to change that array without losing track of what each item represents.

Think about a social media feed.

That feed is basically an array of post objects. When a user creates a new post, the app adds a new object to the feed. Nobody opens the source code, scrolls to the original array, and manually types that post into the starting data.

That would be horrible.

Also, every social media company would need one tired employee per user, armed with coffee and regret.

Instead, the app creates a new object when the user submits the form, then uses JavaScript to add that object to the existing array.

That is what you are practicing here.

## Top to Bottom Matters

JavaScript reads your file from top to bottom, one line at a time.

That means there is an important difference between:

```txt
Building the original roster array
```

and

```txt
Changing the roster later with array methods
```

In Chapter 4, you created the starting roster.

In this chapter, do not go back and manually type the new heroes into the original `leagueRoster` array.

Make the changes **after** the starting roster exists.

Your script should tell the story in order:

```txt
1. Create the original hero objects.
2. Create the starting leagueRoster array.
3. Process the new change requests.
4. Check the updated roster.
```

That order matters because JavaScript only knows about the data that has already been created.

## Array Methods Refresher

For these requests, use array methods to change `leagueRoster`.

You may need:

- `push`
- `unshift`
- `shift`
- `splice`

If those feel rusty, review the handbook chapter on [array end controls](/handbook/JS.VDT.MTH/JS.VDT.COL.ARR_ENDS) before continuing.

The point of this chapter is not just getting the final roster right. The point is practicing how code changes an existing array after the program is already running.

## Change Requests

Process these League requests in order.

### Request 1: Add a new hero to the end

The League approved a new hero named **Quantum Quill**.

Create a hero object from this profile sheet. Then use an array method to add that object to the end of `leagueRoster`.

Do not manually add Quantum Quill inside the original roster array from Chapter 4. This request happens after the starting roster already exists.

```txt
ID: 5
Hero name: Quantum Quill
Civilian name: Priya Nair
Power level: 79
Active status: active
Primary ability: Probability ink
Home city: Ledger Bay
Team assignment: Archive Unit
```

### Request 2: Add an emergency substitute to the beginning

A substitute hero needs to appear at the beginning of the roster while the director checks the stage schedule.

Create a hero object from this profile sheet. Then use an array method to add that object to the beginning of `leagueRoster`.

```txt
ID: 99
Hero name: Placeholder Paladin
Civilian name: Temporary Terry
Power level: 12
Active status: active
Primary ability: Standing in line
Home city: Clipboard City
Team assignment: Substitute Bench
```

### Request 3: Remove the emergency substitute

The director has checked the schedule.

The substitute is no longer needed.

Use an array method to remove **Placeholder Paladin** from the beginning of `leagueRoster`.

### Request 4: Replace a hero who changed their public identity

Echo Eclipse has updated their public identity and team assignment.

Create an updated hero object from this profile sheet. Then use an array method to replace the existing Echo Eclipse record in `leagueRoster`.

```txt
ID: 4
Hero name: Echo Nova
Civilian name: Jordan Vale
Power level: 82
Active status: active
Primary ability: Sound bending
Home city: Harbor City
Team assignment: Vanguard
```

The ID stays the same because this is the same person. Only the public hero record changed.

That is one reason IDs matter: names can change, but the ID still points to the same record.

### Request 5: Update one hero's team assignment

Neon Volt has been moved from **North Squad** to **Vanguard**.

Update only Neon Volt's team assignment.

Do not replace the whole Neon Volt object. Only change the team value.

This request changes one property inside one object. It does not add, remove, or replace an item in the array.

Then log a readable summary of the final change-request result.

