# Debugging → Finding What Went Wrong

Before we talk about debugging, let's break something.

Actually, somebody already took care of that for us.

Welcome to **Weird Mike's Pawn Shop**.

Nobody is completely sure whether "Weird Mike" describes Mike or the pawn shop. Either way, the inventory is unusual and the software needs work.

Mike had his nephew, Mook, put together a program for the shop.

**Do not fix it yet. Run it first.**

The program fails.

That is where debugging begins.

**Debugging** is the process of figuring out why a program is not behaving the way you expect and making a change that fixes the problem.

Sometimes a bug makes JavaScript stop with an error. Sometimes the program keeps running but produces the wrong result. Either way, the useful first move is the same: **observe what actually happened before you start changing code**.

For Weird Mike's program, we are going to use this rhythm:

1. **Run** the program.
2. **Read** what JavaScript reports.
3. **Investigate** that one problem.
4. **Change** the code.
5. **Run again**.

That last step matters.

When you fix one problem, JavaScript may immediately show you another one.

That does not mean your first fix failed.

> **A new error can be progress.**

You will keep this same `main.js` through the entire Error Messages & Stack Traces project. Each successful fix lets JavaScript get a little farther into Mook's program.
