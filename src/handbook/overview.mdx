# Welcome to the JavaScript Gym Handbook!

This handbook is your **intro to JavaScript book** for the playground.
Each chapter focuses on a single standard (like arrays, functions, or iteration),
and each standard has matching practice tickets on the **Challenges** page.

The rhythm we’re aiming for is:

1. **Read a chapter** here in the handbook.
2. **Practice that standard** on the Challenges page.
3. **Come back to the chapter** if you need a refresh.

Over time, you’ll loop through this pattern across standards:

- Value data types → collections → methods → control flow → functions → iteration, and so on.
- Each chapter builds on the last.

---

## How to pair the handbook with challenges

Here’s how to use the site now that the handbook is a first‑class citizen:

1. **Pick a chapter here** that matches a standard, like `JS.PF.ITR` for iteration.
2. **Read the overview** and work through the inline HandbookChallenges. These are short, focused reps using the editor + console.
3. **Switch to the Challenges page** and filter by that same standard. Do the practice tickets that reinforce what you just read.
4. **Return to the handbook** when something feels fuzzy, or when you're ready for a new chapter.

You can absolutely skim ahead, but when in doubt:

- Let the **handbook explain the idea**.
- Let the **challenges stress‑test your understanding**.

The fastest progress comes from bouncing between the two.

## What JavaScript is (and isn’t)

JavaScript isn’t magic. It can feel that way at first, but it’s really a toolbox for manipulating data.

- Posting on Instagram → Create data
- Scrolling your feed → Read data
- Changing your username → Update data
- Deleting a post → Delete data

That’s CRUD, and it’s most of what we do. Our goal here isn’t to teach you every tool in the JavaScript toolbox. It’s to teach you the basic tools you’ll actually use—and when to use them.

### A quick editor note

The workspace opens on `index.html` first because it is the page your code runs inside. For the console-focused exercises in this handbook, click `main.js` in the file tree or editor tab before you start typing—that is where your JavaScript belongs.

## Your first tool: <code>console.log</code>

Think of <code>console.log</code> as your stethoscope—it lets you hear what your code is doing.

```js
console.log("Hello, handbook!");
```

You’ll use it constantly to check values, confirm what ran, and debug surprises.

## How JavaScript runs (top → bottom)

JavaScript reads your file top to bottom, one line at a time. If line 3 uses something that isn’t defined until line 20, you’ll get an error.

```js
console.log(greeting); // ❌ ReferenceError: Cannot access 'greeting' before initialization
const greeting = "hi";
```

We’ll learn patterns that run code later (events, functions), but for now think of your file like a book: top → bottom.

## Comments: notes for humans (and how to toggle them)

Programs are for computers and for people. Comments are short notes the computer ignores but teammates (and future‑you) will appreciate.

- Line comment: anything after <code>//</code> on a line is ignored
- Toggle quickly: press <strong>Ctrl+/</strong> (Windows/Linux) or <strong>Cmd+/</strong> (Mac) to comment/uncomment selected lines

```js
console.log("Visible");
// console.log("Hidden for now"); // toggled off with Ctrl+/ (Cmd+/ on Mac)
console.log("Still visible"); // end-of-line comment is fine, too
```
