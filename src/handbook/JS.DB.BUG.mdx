# Debugging → Lil' Florian's Video Rental Bug Hunt

Lil' Florian's Video Rental specializes in movies no one has heard of...and those that _have_ probably only remember as a weird fever dream. Before opening for the evening, Florian needs a report showing which movies have enough copies and which ones need more.

The program is already written, but it doesn't work yet.

This time, there isn't a new JavaScript tool to learn first. The challenge is to use the tools you already have:

- reproduce the problem,
- read the error message,
- compare the actual output with the expected output,
- add purposeful `console.log()` statements,
- fix one cause at a time,
- and run the program again after every change.

The starter code contains **three bugs**. They aren't three versions of the same mistake. The first one stops the program. The other two let it run while producing a report that is quietly wrong.

  </p>
</Callout>

## Before you call it fixed

A matching report is important, but debugging also means understanding why the repairs worked. Before you open the solution, make sure you can explain:

1. Why the original program stopped before printing anything.
2. Why one inventory item disappeared even after the program could run.
3. Why every movie originally received the same copy status.
4. Which evidence led you to each cause.

If you can explain those four things, you didn't guess your way to working code. You debugged it.

## The rhythm to keep

Real debugging rarely means staring harder until the answer appears. It is a loop:

1. **Reproduce** the problem.
2. **Observe** the actual behavior.
3. **Compare** it with the expected behavior.
4. **Collect evidence** with errors, output, and temporary logs.
5. **Fix one cause.**
6. **Run again.**

That loop will keep working when the programs get bigger—even when the bugs get weirder.
