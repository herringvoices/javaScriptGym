# Iteration → Repeating Actions on Purpose

Welcome! In this chapter you’ll meet another big idea in JavaScript: **iteration** — the way your program repeats a set of actions. Most of the time, that means doing the same kind of work for **each item in an array**.

Now, that might not sound particularly useful… until you need to:

* **total up** everything in a customer’s cart
* **scan** a library’s checked-out books to see whether any are overdue
* **use** data from a database to build a dropdown menu (one option per item)

Notice what those have in common: you’re not dealing with one thing. You’re dealing with a **collection**—a list of cart items, a stack of books, a batch of records. To do anything useful, your code has to move through that collection one item at a time and do the same kind of work each time.

That’s where **loops** come in. Loops are how you tell JavaScript: “Take this set of instructions… and repeat it for each item until we’re done.”

Think of it like a machine that runs the same script over and over.
Set it up to make tacos, and it makes taco after taco until you shut it off.
Set it up to email your grandmother, and—well—she’s going to have questions.

Iteration is that idea in code: a repeatable process, driven by a clear rule that eventually says, “Alright. Stop.”

## Practice · Spot repetition before loops

Before we let JavaScript act as the repeating machine for us, you’ll do things the “manual” way once. For now, **you** are going to be the machine: you’ll repeat the same pattern by hand and feel how repetitive it is.

The examples below assume you already have a `heroes` array in your file with several hero objects. You’ll work with that data directly.

You just acted like a very patient, very manual loop:

* You **started** with the first hero.
* You **stopped** when you ran out of heroes.
* You **stepped** forward by changing the index or picking the next hero yourself.
