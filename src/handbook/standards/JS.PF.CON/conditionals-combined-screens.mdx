# Combined Conditions (AND & OR)

So far, your ladders have mostly checked **one thing at a time**:

* "Is this find big enough?"
* "Is it already cleaned?"
* "Should it go back into the surf?"

That is already useful, but real decisions rarely stop at a single detail. The salvage crew wants rules like:

* "Display only if it is big **and** polished."
* "Reject anything that is too wet **or** too sharp."
* "Keep it if it is from the lighthouse registry **or** it is massive."

To write rules like that you combine conditions with logical operators:

* **`&&`** ("and") -- every check must pass.
* **`||`** ("or") -- at least one check must pass.

You will also meet a handy behavior called **short-circuiting**: JavaScript stops evaluating as soon as it already knows the outcome.

---

## 1) Two checks in a row: `&&` (AND)

Imagine a relic rolling down the sorter:

```js
const item = {
    name: "lantern glass",
    size: 7,
    isPolished: true,
};
```

You only want to send it to the display table if it is both sizeable and already polished. You could nest two `if` statements:

```js
if (item.size >= 6) {
    if (item.isPolished) {
        console.log("Display it.");
    }
}
```

That works, but nested logic becomes hard to scan. The **`&&` operator** lets you combine both screens into a single condition:

```js
if (item.size >= 6 && item.isPolished) {
    console.log("Display it.");
}
```

Read it aloud: "If the item is big enough **and** it is polished, display it."

### Mesh screen picture

Think of `&&` as **two screens in a row** on the same chute:

1. Screen A checks `item.size >= 6`.
2. Screen B checks `item.isPolished`.

To reach the chute, the item must pass **both** screens. Failing the first screen means it never even sees the second.

## 2) Either-or rules: `||` (OR)

Some rules do not need every screen to pass. Sometimes **either** condition is enough.

Picture the reject funnel: you toss an item if it is too saturated with seawater **or** it is dangerously sharp.

```js
const item = {
    name: "rusty shard",
    moisture: 0.7,
    edgeRating: "sharp",
};

if (item.moisture > 0.5 || item.edgeRating === "sharp") {
    console.log("Discard for safety.");
}
```

Read it aloud: "If the item is too wet **or** it is sharp, discard it."

### Mesh screen picture

Think of `||` as **two screens feeding the same chute**. Passing either screen drops the find into the same bin.

## Technical Vocabulary

| Term               | Plain-English meaning                                   | Tiny example                               |
| ------------------ | ------------------------------------------------------- | ------------------------------------------ |
| logical AND (`&&`) | Both checks must pass                                   | `size >= 6 && item.isPolished`             |
| logical OR (`||`)  | At least one check must pass                            | `item.type === "token" || item.size >= 8` |
| short-circuiting   | Stopping early once the result is known                 | `false && needsCleaning()`                 |
| combined condition | One condition made from smaller ones with `&&` or `||` | `(isTagged && isDry) || isMassive`         |
| grouping           | Using parentheses to keep related checks together       | `(A && B) || C`                            |
| guard check        | Early exit that prevents the rest of the code from running | `if (!item) return;`                    |
| threshold          | The comparison boundary used in a condition             | `item.moisture <= 0.2`                     |
