# Array Methods → Lookup Methods

## Lookups and validation: `find()`, `some()`, `every()`

So far you’ve used array methods to **transform** a list (`map()`) or **create a subset** (`filter()`). Now you’ll use methods that **ask the list questions**.

`find()`, `some()`, and `every()` let you **look up** information in an array, or **validate** something about it.

Instead of building a brand-new array (like `map()` or `filter()`), these methods **ask the array a question** by running your callback on items until they know the answer.

This callback is often called a **predicate**: it answers “yes or no?” for each item.

Here are the three big ones:

- `find()` → “Give me the one item that matches a rule.” → returns **one item** (or `undefined`)
- `some()` → “Does *any* item match a rule?” → returns **true/false**
- `every()` → “Do *all* items match a rule?” → returns **true/false**

---

### 1) `find()` — get the one match

`find()` runs your predicate on each item and:

- returns the **first** item where the callback returns `true`
- returns `undefined` if it never finds a match

**Example:**

```js
const student3 = students.find((s) => s.id === 3);
```

Now `student3` is the student object whose `id` is `3` (or `undefined` if that student doesn’t exist).

What about an example from real life? Maybe you’re trying to find the first clean shirt in a chaotic laundry pile:

```js
const firstCleanShirt = shirts.find((s) => s.isClean);
```

Or maybe you’re trying to find the first gas station that’s actually open (because your gas light light is judging you):

```js
const openStation = stations.find((st) => st.isOpen);
```
Most often, when you use `find()`, you're looking for one specific thing, and you're trying to find it by a unique identifier that only that thing has.

For example: you're trying to pick up your kid from daycare. They are one of two kids named "Hoffle Sturp McWoof." So the daycare looks them up by a unique id they gave them when you first signed them up:

```js
const yourKidId = 14
const yourKid = kids.find(k => k.id === yourKidId)
```

We could do this all day! The point is: `find()` is for when you want **one specific item**, not a whole subset.

---

### 2) `some()` — does any match?

`some()` checks whether **at least one** item passes your predicate. It runs your callback on items and:

- returns `true` as soon as it finds one item where the callback returns `true`
- returns `false` if it checks everything and nothing matches

**Example:**

```js
const hasAnyFines = fines.some((f) => f.studentId === student.id);
```

Now `hasAnyFines` is `true` if this student has at least one fine record, otherwise `false`.

What about an example from real life? Maybe you’re checking your fridge for *any* snack that counts as “food”:

```js
const hasAnyFood = fridge.some((item) => item.isEdible);
```

Or you’re checking if *any* of your friends are free tonight before you bother forming a group chat:

```js
const anyoneFree = friends.some((f) => f.isFreeTonight);
```

The point here is: `some()` is for “**is there at least one?**”

---

### 3) `every()` — do all match?

`every()` checks whether **all** items pass your predicate. It runs your callback on items and:

- returns `false` as soon as it finds one item where the callback returns `false`
- returns `true` only if every item passes

A common pattern is: **filter down to the relevant items first**, then use `every()` to validate.

**Example:**

```js
const studentGrades = grades.filter((g) => g.studentId === student.id);
const needsTutoring = studentGrades.every((g) => g.grade < 2);
```

Now `needsTutoring` is `true` if *every* one of that student’s grades is below 2.

What about an example from real life? Maybe you’re checking whether everyone in a group chat has RSVP’d before you book the thing:

```js
const everyoneReplied = invites.every((i) => i.hasResponded);
```

Or maybe you’re checking whether all your devices are charged before a trip (and yes, this is how you end up packing 14 cables):

```js
const allCharged = devices.every((d) => d.batteryPercent >= 80);
```

One weird-but-important edge case: `every()` on an empty array returns `true`. That’s not a bug—it’s just how the logic works. In real apps, you often add a quick check like “do we even have any items?” before trusting the result:

```js
const hasGrades = studentGrades.length > 0;
const needsTutoring = hasGrades && studentGrades.every((g) => g.grade < 2);
```

---

### Teacher lookup chaining

You’ll also often use these lookups together—one right after another: find a student, then use their data to find their teacher.

```js
const student3 = students.find((s) => s.id === 3);
const teacher = teachers.find((t) => t.id === student3.homeroomTeacherId);
```
<Callout type="tip" title="A Look Ahead">
In the next section you'll see method chaining — calling array methods one after another (for example: `students.filter(...).map(...).find(...)`). Chaining can make code shorter and easier to read...and can make you feel very clever and proud of yourself, which is also nice.
</Callout>
