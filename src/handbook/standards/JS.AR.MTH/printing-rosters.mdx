# Array Methods → Putting it All Together

## Method chaining: letting one step feed the next

By now you’ve noticed something important about array methods:

Most of them **return a value**.

And if you have a value, you can immediately do the next step.

That’s all *method chaining* is: a little pipeline where **each step hands its result to the next step**.

### What “the next step” really means

When you write this:

```js
students.filter(...).map(...).join("\n");
```

JavaScript evaluates it left to right:

1. `students.filter(...)` runs first and returns a **new array**
2. then `.map(...)` runs on that returned array and returns **another new array**
3. then `.join(...)` runs on that returned array and returns a **string**

So chaining is basically:

**result of step 1 → becomes the input for step 2 → becomes the input for step 3**

---

## Example 1: Party planning (filter → map)

Maybe you’re texting invitations. You only want to invite people who are free, and you want to turn each person into a message string.

```js
const messages = friends
  .filter((f) => f.isFreeTonight)
  .map((f) => `Hey ${f.name}, want to hang out?`);
```

Read it step-by-step:

- start with `friends`
- **filter**: keep only friends where `isFreeTonight` is true
  → result: a smaller array (just the free friends)
- **map**: turn each friend into an invitation message
  → result: an array of strings (messages)

If you said this out loud, it’s basically:

“From all my friends, keep the free ones, then turn them into texts.”

---

## Example 2: Grocery trip (filter → map → join)

Maybe you’ve got a grocery list, but you only want items that are urgent, and you want one string you can paste into a text message.

```js
const textToSend = groceries
  .filter((g) => g.isUrgent)
  .map((g) => g.name)
  .join(", ");
```

Read it step-by-step:

- start with `groceries`
- **filter**: keep only urgent items
  → result: array of urgent grocery objects
- **map**: transform each object into just its `name`
  → result: array of strings (names)
- **join**: combine the names into one comma-separated string
  → result: one string you can send

So the output type changes as you go:

`array of objects → array of objects → array of strings → string`

That’s normal. You’re reshaping the data until it’s exactly what you need.

## Example 3: “Do we have a problem?” (filter → some)

Sometimes a chain ends in a boolean question.

Maybe you want to know if there are **any** overdue books for a specific student:

```js
const hasOverdueBooks = books
  .filter((b) => b.borrowerId === student.id)
  .some((b) => b.isOverdue);
```

Read it step-by-step:

- start with `books`
- **filter**: keep only the books borrowed by this student
  → result: array of that student’s books
- **some**: check whether any of those books are overdue
  → result: `true` or `false`

So now `hasOverdueBooks` is a simple boolean. It’s either `true` (yes, at least one is overdue) or `false` (nope, they’re good).

---

## Example 4: A chain that ends in `reduce()` (map → reduce)

Maybe you want the total cost of a cart, but you want to apply tax first (or some kind of transformation) before totaling.

```js
const totalWithTax = cart
  .map((item) => item.price * 1.1)
  .reduce((sum, price) => sum + price, 0);
```

Read it step-by-step:

- start with `cart`
- **map**: turn each item into its taxed price
  → result: array of numbers (prices)
- **reduce**: add those numbers into one total
  → result: one number

Again: each step returns something, and the next method runs on **that**.

---

## What chaining is *not*

Chaining isn’t “doing three things at once.”

It’s doing one thing in small, readable steps. Each dot is like a little piece of punctuation: it waits for the previous step to finish and hand back a result, then it uses that result to move on to the next step.

### The readability rule

Chaining is awesome… until it becomes a spaghetti slide.

If a chain makes you read it twice, split it into a couple variables:

```js
const urgentItems = groceries.filter((g) => g.isUrgent);
const names = urgentItems.map((g) => g.name);
const textToSend = names.join(", ");
```

Same logic, just easier to debug and easier to teach.

## Technical Vocabulary

| Term              | Plain-English meaning                                       | Tiny example                                                |
| ----------------- | ----------------------------------------------------------- | ----------------------------------------------------------- |
| callback function | A function you pass into another function to run later      | `students.map((s) => s.firstName)`                         |
| map               | Transform every item into a new value (same length array)   | `ids = students.map((s) => s.id)`                           |
| filter            | Keep only items that match a rule (subset array)           | `petOwners = students.filter((s) => s.pets > 0)`            |
| find              | Return the first item that matches, or `undefined`         | `students.find((s) => s.id === 3)`                          |
| some              | Check if at least one item matches (boolean)               | `fines.some((f) => f.studentId === s.id)`                   |
| every             | Check if all items match (boolean)                         | `studentGrades.every((g) => g.grade < 2)`                   |
| reduce            | Roll an array into a single result                         | `students.reduce((total, s) => total + s.pets, 0)`         |
| transform         | Change the shape of data into something more useful        | `students → ["First Last", ...]` via `map()`               |
| subset            | Smaller array built from items that passed a test          | `dragonportHouse` from `students.filter(...)`               |
| summarize         | Combine many values into one meaningful result             | `countPets(dragonportHouse)`                               |
| chain             | Call multiple methods in a row to build a data pipeline    | `grades.filter(...).every(...)` or `blocks.join("\n\n")` |

---

## What to remember

- Array methods like `map`, `filter`, `find`, `some`, `every`, and `reduce` all take **callbacks**.
- `map` transforms items into a new array of the **same length**.
- `filter` selects matching items to create a **subset array**.
- `find` returns **one** matching item (or `undefined` if none match).
- `some` and `every` answer **boolean questions** about your data.
- `reduce` produces **one result** from many items (like a total or summary object).
- Chaining methods is just step-by-step transformation—keep each step small and the pipeline stays readable.
