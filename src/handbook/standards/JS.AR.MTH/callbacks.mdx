# Array Methods → Callback Functions

## 1) Callback functions

Array methods like `map`, `filter`, `find`, `some`, `every`, and `reduce` all share a common pattern: **you pass them a function**, and they call that function for each item (or until they know the answer).

<Callout type="tip" title="Does that sound familiar?">
It should! Each of these functions _**iterate**_ through an array; performing pre-determined actions on each item in that array, just like what we did with our `for...of` loops a couple of chapters ago.
</Callout>

That passed-in function is a **callback**. The array method controls **when** it runs and which values it passes in; your callback controls **what to do** with each value.

---

### A function can accept a function

```js
const announce = (fn) => {
  fn();
};

announce(() => console.log("Boarblemish calls!"));
```

Here, `announce` doesn’t know what will happen; it just promises to call `fn`. The caller decides which function to pass.

I know, in that example callback functions seem pretty useless, but hopefully by the end of this chapter, you'll see how powerful they can be!

<Callout type="note" title="Anonymous functions (the () => {} shape)">
In `announce(() => console.log("Boarblemish calls!"))`, the `() => console.log()` part is an **anonymous function** (a function with no name) being passed in as the callback.

How to read it:
- `()` = the parameters (none here)
- `=>` = “this is a function”
- `console.log("Boarblemish calls!")` = the code it runs

A lot of callback functions follow that same pattern, so it's good to get familiar with it now.

</Callout>

---

### A callback can receive data

```js
const runForEachStudent = (list, action) => {
    for (const s of list) {
        action(s);
    }
};

runForEachStudent(students, (s) => console.log(s.firstName));
```

`runForEachStudent` loops over a list and calls your `action` callback once for each student, handing it the current `s`.

---

### Callbacks often return something

In many array methods:

- The callback **returns a new value** for each item (`map`).
- Or it returns a **boolean** to say “keep this one” or “skip it” (`filter`).
- Or it updates a **running total** (`reduce`).

You’ll see each of those patterns in later sections. For now, just get comfortable **passing a function into another function** and using the value it receives.

<Callout type="tip" title="When can you skip () and {}?">
Arrow functions have a few handy shortcuts:

- **Parameters**:
  - One parameter? You can skip the parentheses: `s => s.firstName`.
  - Zero or many parameters? Keep them: `() => ...` or `(student, index) => ...`.
- **Body**:
  - Doing or returning **one thing**? You can skip `{}` and return the expression directly: `s => s.firstName`.
  - Doing/returning **two or more things**? Use `{}` and remember `return`:

    ```js
    (s) => {
      const fullName = `${s.firstName} ${s.lastName}`;
      return fullName;
    };
    ```

Use the short form when it stays readable; switch to the block form when you need more steps.
</Callout>
