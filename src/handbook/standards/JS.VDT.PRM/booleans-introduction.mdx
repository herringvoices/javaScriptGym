# Data Types → Booleans (plus null and undefined)

Strings let us **describe** the Movie Night Planner. Numbers let us **count** guests, snacks, and bowls. Now we need a way to **decide** whether things are ready. That job belongs to the **boolean** type: a light switch that’s either **on (`true`)** or **off (`false`)**—no dimmers, no maybes.

## 1) Status lights for the plan (literal booleans)

Sometimes you already know the answer to a yes/no question. Store it directly as <code>true</code> or <code>false</code>.

```js
let hasSentInvites = false;
const captionsEnabled = true;
console.log(hasSentInvites, captionsEnabled); // false true
```

Name booleans so you can read them out loud: “<em>has sent invites</em> is false” makes sense. Avoid double negatives like <code>isNotReady</code>—your future self will thank you.

## 2) Comparisons: ask the numbers yes/no questions

We don’t want to hand-type <code>true</code> and <code>false</code> for every scenario. Instead, we <strong>derive booleans</strong> by asking the numbers questions with comparison operators.

```js
const maxGuests = 6;
const isOverCapacity = numGuests > maxGuests;
const hasEnoughSnacks = snacksOnHand >= totalSnacksNeeded;
```

Read the comparison aloud: “Is <em>numGuests greater than maxGuests?</em>” → the result becomes the boolean.

Common operators you’ll use here:

| Symbol | Reads like                         | Example                              |
| ------ | ---------------------------------- | ------------------------------------ |
| `>`    | greater than                       | `numGuests > maxGuests`              |
| `>=`   | greater than or equal to           | `snacksOnHand >= totalSnacksNeeded`  |
| `<`    | less than                          | `bowlsNeeded < 4`                    |
| `<=`   | less than or equal to              | `numGuests <= 10`                    |
| `===`  | strictly equal (same value & type) | `location === "living room"`        |
| `!==`  | strictly not equal                 | `snack !== "kettle corn"`           |

<Callout type="tip" title="Remember the assignment rule">
  <p className="m-0"><strong>`=`</strong> still means “evaluate the entire right-hand side first, then store the single resulting value in the variable on the left.” Comparisons live on the right-hand side.</p>
</Callout>

## 3) Negation (`!`) turns one rule into its opposite

The exclamation mark means “not.” Use it to flip a boolean or to invert a whole condition.

```js
let isLightsDimmed = false;
isLightsDimmed = !isLightsDimmed; // true
const shouldSendReminder = !hasSentInvites; // true if invites aren’t sent yet
```

Every UI toggle you’ve ever built uses this pattern somewhere: <code>isOpen</code>, <code>isEditing</code>, <code>isMuted</code>, <code>isDarkMode</code>—they all flip with <code>!</code>.

## 4) `null` vs `undefined`: empty on purpose vs empty by accident

Movie Night will eventually highlight a VIP friend or a featured snack, but maybe you haven’t chosen them yet. That’s where <code>null</code> comes in—it says “we meant for this to be empty right now.” <code>undefined</code> usually means “we never set this (or we looked in the wrong place).”

```js
let vipGuest = null;          // placeholder on purpose
let backupSnack;              // undefined because we never assigned
const snackPlan = { main: snack };
console.log(snackPlan.bonusDessert); // undefined (property missing)

vipGuest = "Aunt Jo";        // later we fill it in
console.log(vipGuest);        // "Aunt Jo"
```

<Callout type="tip" title="When to use which">
  <p className="m-0"><strong>Use <code>null</code></strong> when you want to signal “this will have a value later.” Expect <strong><code>undefined</code></strong> from JavaScript when you forget to assign or you ask for something that doesn’t exist.</p>
</Callout>

## Common gotchas (mini road signs)

* Don’t put booleans in quotes—<code>"true"</code> is a string, not a boolean.
* <code>=</code> assigns, <code>===</code> compares, <code>!==</code> compares the opposite.
* Wrap the part you’re negating in parentheses when it improves readability: <code>const hasSpace = !(numGuests > maxGuests);</code>
* Use <code>null</code> to mark “waiting for real data later,” expect <code>undefined</code> when you forgot to assign or the property doesn’t exist.

## Technical Vocabulary

| Term                | Plain-English meaning                         | Tiny example                               |
| ------------------- | --------------------------------------------- | ------------------------------------------ |
| boolean             | A yes/no value                                | `const isReady = true`                     |
| comparison operator | Symbol that asks a question about numbers     | `numGuests > maxGuests`                    |
| assignment operator | Stores the result of an expression            | `isFull = seatsTaken === seatsTotal`       |
| negation operator   | Flips a boolean                               | `isLightsDimmed = !isLightsDimmed`         |
| null                | Empty on purpose (placeholder)                | `let vipGuest = null`                      |
| undefined           | Empty by accident / not set / missing property| `extras.bonusDrink // undefined`           |

## Wrap-up

* Booleans store the answers to the yes/no questions your app keeps asking.
* Derived booleans come from comparisons—ask the question on the right side of <code>=</code>.
* Use <code>!</code> to flip a value or invert a rule without rewriting the logic.
* Reach for <code>null</code> when you deliberately leave a slot empty, and expect <code>undefined</code> when something was never filled in.
