# Rendering the Potion Shelf List

You already have the app shell on the page. Right now the Shelf panel is still doing the “trust me, content will arrive later” thing.

In this section, you’ll do one very specific move:

**Take an array of objects and turn it into a list of `<li>` elements.**

While you do that, you’ll add one small upgrade that will matter *a lot* in the next sections:

**Each `<li>` will store the potion’s id using a `data-*` attribute.**

Why? Because clicks happen in the DOM world, but the real potion info lives in the data world. `data-*` is the bridge between them.

---

## The idea: turn data into a list of HTML strings

When you render a list, the pattern is:

1. Get an array
2. Map each item to an HTML string
3. Join the strings into one big string
4. Inject it into the DOM

Here’s the smallest version that still feels real:

```js
const items = ["A", "B", "C"];

const listItems = items
  .map(item => `<li>${item}</li>`)
  .join("");

document.querySelector("#somewhere").innerHTML = `<ul>${listItems}</ul>`;
```

That’s the core “render a list” move. You’ll use it constantly.

---

## `data-*` attributes: hiding helpful data in plain sight

A `data-*` attribute is just a custom HTML attribute you can put on an element.

```html
<li data-potion-id="3">Glacier Draught</li>
```

It doesn’t change how the element looks. It’s information attached to the element.

Later, when a click happens, you can ask that element which potion id it represents.

---

## Generic example: ids on list items

```js
const pets = [
  { id: 1, name: "Dexter" },
  { id: 2, name: "Mochi" }
];
```

A useful render could produce:

```html
<li data-pet-id="1">Dexter</li>
<li data-pet-id="2">Mochi</li>
```

The user sees the name while your code still has the id available for future interaction.

---

<Callout type="tip" title="String interpolation is your friend">
  When you build markup from data, template literals keep the HTML readable. We’re sticking with them instead of turning the markup into a ransom note made of concatenated strings.
</Callout>

## Recap

You can now:

- Render a full list by mapping data into HTML strings
- Combine those strings with `join("")`
- Inject the final markup into the DOM with `innerHTML`
- Label DOM elements with `data-*` attributes so events can identify them later

Next up, we’ll start listening for clicks, and those `data-potion-id` attributes will suddenly feel extremely clever.

---

## Technical Vocabulary

| Term               | Meaning                                                                 |
| ------------------ | ----------------------------------------------------------------------- |
| `map()`            | Builds a new array by running a function once per item.                 |
| `join("")`         | Combines an array of strings into one string with nothing between them. |
| template literal   | A string written with backticks that supports `${}` interpolation.      |
| `data-*` attribute | A custom HTML attribute for storing extra info on an element.           |
| `innerHTML`        | Replaces an element’s content with new HTML markup.                     |
