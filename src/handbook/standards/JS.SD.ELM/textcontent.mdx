# textContent: Put Plain Text on the Page

## Page Goal

Learners make their first visible DOM update.

## Concepts

- `textContent` updates plain text.
- `textContent` does not create HTML.
- Assigning to a DOM property updates the visible page.

In the last chapter, your JavaScript found an element in the DOM.

That was an important first step.

But it probably also raised a very reasonable question:

> Cool. We found the element. Now can we actually do something with it?

Yes.

Now that we have selected the `#app` element and stored it in a variable, JavaScript can use that variable to change what the user sees.

In this chapter, we are going to use a property called `textContent`.

`textContent` gives us a simple way to put plain text inside an element.

That means this chapter is our first real “JavaScript changed the page” moment.

## Selecting an Element Is Not the Same as Changing It

At the end of the last chapter, your code looked like this:

```js
const app = document.querySelector("#app");

console.dir(app);
```

That code successfully found the element.

But it did not change anything visible on the page.

Why not?

Because selecting an element only gives JavaScript access to it.

It is like pointing at a box and saying:

> There it is.

Helpful. But not very dramatic.

If we want the user to actually see something new, JavaScript has to do more than select the element.

It has to change something about that element.

## What `textContent` Does

Every DOM element has properties that JavaScript can read or change.

One of those properties is `textContent`.

`textContent` represents the plain text inside an element.

<Callout type="tip" title="Problem this solves">
  <p className="m-0">After selecting an element, you need a specific property to change what the user sees. <code>textContent</code> is the simplest first property because it only deals with plain text.</p>
</Callout>

That means we can write code like this:

```js
app.textContent = "Potion Shelf loading...";
```

This line tells JavaScript:

> Take the element stored in `app` and set its text content to `Potion Shelf loading...`

When the browser runs that line, the text appears on the page.

So now our code can do two different jobs:

- `document.querySelector("#app")` finds the element
- `app.textContent = ...` changes the text inside the element

That is an important distinction.

First we select. Then we update.

## Putting It Together

Your code should now look like this:

```js
const app = document.querySelector("#app");

app.textContent = "Potion Shelf loading...";
```

Let’s slow that down.

| Code                             | Meaning                                              |
| -------------------------------- | ---------------------------------------------------- |
| `const app`                      | Create a variable named `app`                        |
| `document.querySelector("#app")` | Find the element with an id of `app`                 |
| `app.textContent`                | Access the text content property of that element     |
| `=`                              | Set the property to a new value                      |
| `"Potion Shelf loading..."`      | The plain text that should appear inside the element |

Once this code runs, the page should no longer look empty.

It should show this text:

```txt
Potion Shelf loading...
```

That is our first visible DOM update.

Not a whole app yet. But definitely progress.

## `textContent` Changes Text, Not HTML

This part matters a lot.

`textContent` is for plain text.

It does **not** create HTML structure.

For example, look at this code:

```js
notice.textContent = "<strong>Shop is open</strong>";
```

The browser will show the characters exactly as text rather than creating a `<strong>` element.

Why?

Because `textContent` does not interpret HTML tags. It only places plain text inside the element.

<Callout type="warn" title="Plain text only">
  <p className="m-0">Use <code>textContent</code> when you want text to appear exactly as written. If you need real HTML elements, wait for <code>innerHTML</code> on the next page.</p>
</Callout>

## What You Should Notice

There are a few important ideas packed into this small example.

First, JavaScript really is changing the page now.

That means the DOM is not just something we inspect in the console. It is something we can update.

Second, the `app` variable matters because it stores the selected element.

That variable is how our code knows *which* part of the page to change.

Third, `textContent` replaces the plain text inside the element.

When you change:

```js
app.textContent = "Potion Shelf loading...";
```

to:

```js
app.textContent = "Potion Shelf ready.";
```

The old text does not stay there. It gets replaced by the new text.

That is the second major DOM idea in this section:

> Once JavaScript has selected an element, it can change what the user sees.

## Technical Vocabulary

| Term          | Meaning                                                     |
| ------------- | ----------------------------------------------------------- |
| `textContent` | A property that represents the plain text inside an element |
| property      | A value that belongs to an object                           |
| plain text    | Regular text, not interpreted as HTML structure             |
| DOM update    | A change JavaScript makes to the page through the DOM       |
| replace       | To overwrite an old value with a new one                    |
