# `join("")`: One Big String for `innerHTML`

Potion Shelf can now turn the whole `potions` array into an array of `<li>` strings.

That is almost what we need.

Almost.

At the end of the last page, you had this:

```js
const potionHTMLArray = potions.map(PotionItem);

console.log(potionHTMLArray);
```

That gave us a new array.

Not an array of potion objects anymore.

An array of HTML strings.

Something like this:

```js
[
  "<li>Healing Potion</li>",
  "<li>Invisibility Potion</li>",
  "<li>Mana Potion</li>"
]
```

That is progress.

Real progress.

But Orborb is not paying us to make a beautiful console log.

They want customers to see the potions on the page.

So now we need the final step:

```txt
array of li strings → one HTML string → DOM
```

That is where `join("")` comes in.

## We Have Many Strings, But `innerHTML` Needs One String

At this point, your code should look like this:

```js
import { getPotions } from "./database.js";

function PotionItem(potion) {
  return `<li>${potion.name}</li>`;
}

const app = document.querySelector("#app");

app.innerHTML = `
  <header>
    <h1>Potion Shelf</h1>
    <p>Rare brews, trusted classics, and suspiciously glowing mystery blends.</p>
  </header>

  <main>
    <section>
      <h2>Available Potions</h2>
      <ul id="potion-list"></ul>
    </section>
  </main>
`;

const potionList = document.querySelector("#potion-list");

const potions = getPotions();

const potionHTMLArray = potions.map(PotionItem);

console.log(potionHTMLArray);
```

The important part is this line:

```js
const potionHTMLArray = potions.map(PotionItem);
```

That line gives us an array of strings.

But `innerHTML` works best when we give it one string of HTML.

Not an array.

This is the missing step:

```txt
array of potion objects
→ array of li strings
→ one HTML string
```

Right now, we have the middle part.

We need to combine the array into one string before we hand it to the DOM.

## What `join()` Does

`join()` is an array method.

It takes all the items in an array and combines them into one string.

For example, imagine this smaller array:

```js
const words = ["Potion", "Shelf"];
```

If we use `join(" ")`, JavaScript combines the items with a space between them:

```js
words.join(" ");
```

That gives us:

```txt
Potion Shelf
```

The value inside the parentheses tells JavaScript what to put between each item.

That value is called the separator.

So this:

```js
words.join(" ")
```

means:

> Combine the items into one string and put a space between them.

For our potion list, we do not want spaces, commas, or anything extra between the `<li>` strings.

We want the list items to sit directly next to each other in one HTML string.

So we will use an empty string as the separator:

```js
join("")
```

That means:

> Combine the items into one string and put nothing between them.

Tiny string. Big responsibility.

## Why the Empty String Matters

This part is easy to miss.

If you call `join()` without giving it a separator, JavaScript uses commas by default.

So this:

```js
potionHTMLArray.join()
```

would create a string like this:

```html
<li>Healing Potion</li>,<li>Invisibility Potion</li>,<li>Mana Potion</li>
```

See those commas?

Not invited.

If we put that string into the DOM, the browser would show commas between the list items.

That is not what we want.

We want this:

```html
<li>Healing Potion</li><li>Invisibility Potion</li><li>Mana Potion</li>
```

So we need to be specific:

```js
potionHTMLArray.join("")
```

The empty string tells JavaScript:

> Put nothing between the strings when you combine them.

No commas.

No spaces.

No weird punctuation wandering into Orborb’s storefront.

## Use `join("")` After `map()`

Now replace these lines:

```js
const potionHTMLArray = potions.map(PotionItem);

console.log(potionHTMLArray);
```

with this:

```js
const potionHTML = potions.map(PotionItem).join("");
```

Let’s slow that down.

| Code               | Meaning                                                  |
| ------------------ | -------------------------------------------------------- |
| `potions`          | Start with the array of potion objects                   |
| `.map(PotionItem)` | Turn each potion object into an `<li>` string            |
| `.join("")`        | Combine the array of `<li>` strings into one HTML string |
| `const potionHTML` | Store the final HTML string in a variable                |

This line:

```js
const potionHTML = potions.map(PotionItem).join("");
```

means:

> Take the potion array, turn each potion into an `<li>` string, combine those strings into one big HTML string, and store the result in `potionHTML`.

This is method chaining.

That just means one method runs, and then another method runs on the result.

Here is the order:

```txt
potions.map(PotionItem)
```

creates an array of `<li>` strings.

Then:

```txt
.join("")
```

runs on that new array and turns it into one string.

So the full transformation is:

```txt
potions array → map() → array of li strings → join("") → one HTML string
```

That final string is ready for `innerHTML`.

Finally.

Orborb can stop hovering over our shoulder.

Maybe.

## Put the HTML String in the DOM

Now that we have one HTML string, we can put it inside the list.

Add this line after the `potionHTML` variable:

```js
potionList.innerHTML = potionHTML;
```

Your new rendering code should look like this:

```js
const potions = getPotions();

const potionHTML = potions.map(PotionItem).join("");

potionList.innerHTML = potionHTML;
```

This line:

```js
potionList.innerHTML = potionHTML;
```

tells JavaScript:

> Take the final HTML string and place it inside the potion list.

Refresh the preview.

You should now see every potion appear under **Available Potions**.

Not one potion.

Not an empty list.

The full list.

We made it.

The shelf has potions.

## The Full Render Pipeline

This page completes the first full version of our render pipeline.

Here is the whole idea:

```txt
array of potion objects
→ array of li strings
→ one HTML string
→ DOM
```

In code, that looks like this:

```js
const potionHTML = potions.map(PotionItem).join("");

potionList.innerHTML = potionHTML;
```

The first line prepares the HTML.

The second line renders it.

That distinction matters.

`map()` and `join("")` are data transformation steps.

They happen inside JavaScript.

They do not change the page by themselves.

The DOM changes when this line runs:

```js
potionList.innerHTML = potionHTML;
```

That is the line that changes what the user sees.

## What You Should Notice

This is the first time Potion Shelf renders the full potion list.

Before this page, we had the data.

Then we rendered one object.

Then we moved the one-object pattern into `PotionItem`.

Then we used `map()` to create an array of `<li>` strings.

Now we have used `join("")` to combine those strings into one final HTML string.

That gives us the next major idea in this section:

> `innerHTML` needs one HTML string, so we use `join("")` to combine an array of HTML strings before rendering.

The complete rendering flow now looks like this:

```txt
data → HTML string → DOM
```

More specifically:

```txt
potions → map(PotionItem) → join("") → potionList.innerHTML
```

That is the core pattern.

The data starts in JavaScript.

`PotionItem` describes how one object should look as HTML.

`map()` repeats that pattern for every object.

`join("")` combines the results into one string.

`innerHTML` places that string into the DOM.

Potion Shelf now works.

It is not fancy yet.

There are no buttons, filters, dropdowns, or user interactions.

But the page can render a full list from data.

That is a real app pattern.

## Technical Vocabulary

| Term              | Meaning                                                          |
| ----------------- | ---------------------------------------------------------------- |
| `join()`          | An array method that combines array items into one string        |
| separator         | The value placed between items when an array is joined           |
| empty string      | A string with no characters, written as `""`                     |
| `join("")`        | Combines array items into one string with nothing between them   |
| method chaining   | Calling one method and then another method on the result         |
| `potionHTML`      | A variable that stores the final HTML string for the potion list |
| render pipeline   | The sequence of steps that turns data into visible DOM content   |
| final HTML string | The complete string of HTML that can be assigned to `innerHTML`  |
