# `ProfileItem` (One profile in, one `<li>` out)

Right now, we’re trying to build a page that shows profiles based on data.

You *could* write the HTML for a profile directly in `/scripts/main.js`… but then:

- If you need multiple profiles, you’ll repeat yourself.
- If the layout changes, you’ll have to fix it everywhere.
- If you’re on a team, everyone editing the same file gets messy.

Instead, we’re going to make a tiny component: a function that takes **one profile object** and returns **one `<li>` string**.

<Callout type="note" title="Components">
- When a function `return`s an HTML string, we call that function a **component**.
- By convention, components are **Capitalized** so they stand out when you’re scanning code.
</Callout>

## Step 3: A very short module note (`type="module"`, `export`, `import`)

In `/index.html`, your script tag looks like this:

```html
<script type="module" src="/scripts/main.js"></script>
```

That `type="module"` tells the browser: “This file is a module.” Modules are what allow you to:

- **`export`** something from one file
- **`import`** it into another file

The pattern you need right now is simple:

- If another file needs to use it → `export` it
```js
//inside sayHello.js
export const sayHello = () => "Hello!"
```
- If you want to use something from another file → `import` it
```js
//inside main.js
import {sayHello} from "./sayHello.js"
console.log(sayHello())
```

### Note the syntax: imports & exports

Here are some more examples of the syntax you'll use to `import`/`export` in your modules:

- `export` (multiple per file):

```js
export function sayHello() { return "Hi"; }
export const PI = 3.14;
```

- `import` (use curly braces):

```js
import { sayHello, PI } from "./utils.js";
```

<Callout type="note" title="Dot-Slash">
- That `./` before the file name just means the file you're importing is in the same directory (or folder) as the file you're working in.
- If it were one directory up, we'd use `../` with two dots before the filename.
- If it were in a neighboring directory called `styles`, we'd use `../styles/` before the filename.
</Callout>
