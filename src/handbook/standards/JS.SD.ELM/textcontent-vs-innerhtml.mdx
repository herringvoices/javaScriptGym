# textContent vs innerHTML

When you have a DOM element stored in a variable, you have to decide what kind of update you’re making:

- Are you trying to show plain text?
- Or are you trying to render HTML structure?

That’s the difference between `textContent` and `innerHTML`.

---

## textContent is text-only

`textContent` is the simplest way to update the screen.

Whatever string you give it will show up as literal text. The browser won’t try to “treat it like HTML.”

That’s why it’s great for:

- status messages (Loading..., Saved!, No results found)
- counters (3 profiles)
- simple labels that don’t need tags

### Example

```js
const status = document.querySelector("#status");

// This is NOT HTML to the browser.
// It's just characters.
status.textContent = "<strong>Saved!</strong>";
```

On the page, you’ll literally see:

```txt
<strong>Saved!</strong>
```

Because `textContent` prints the characters exactly as written.

---

## innerHTML is HTML-capable

Sometimes plain text isn’t enough. You don’t just want words — you want elements: headings, lists, cards, sections, containers.

That’s what `innerHTML` is for.

When you set `innerHTML`, the browser treats your string as HTML markup:

- it reads your string
- creates real DOM nodes from it
- replaces the element’s contents with those nodes

### Example

```js
const status = document.querySelector("#status");

// This WILL be treated as HTML.
// The browser creates a real <strong> node.
status.innerHTML = "<strong>Saved!</strong>";
```

Now the word Saved! is bold, because a real `<strong>` element was created.

---

## The key choice

You don’t need to memorize a bunch of rules. Just ask one question:

If you want only text, use `textContent`.

If you want HTML structure, use `innerHTML`.
