# Selecting Rendered Elements: Find the List

Potion Shelf now has a real app shell.

That is a big step up from a plain text message.

The page has a title, a little descriptive text, a main section, and an empty list where Orborb's potions will eventually appear.

That empty list is important.

```html
<ul id="potion-list"></ul>
```

Right now, it is just sitting there. Quiet. Patient. Probably glowing a little.

But soon, we will use JavaScript to put potion data inside it.

Before we can do that, JavaScript needs to select the list.

And that is where we are going to meet one of the most common beginner DOM bugs:

> You cannot select an element that does not exist yet.

## The List Exists Because `innerHTML` Created It

At this point, your code should look like this:

```js
const app = document.querySelector("#app");

app.innerHTML = `
  <header>
    <h1>Potion Shelf</h1>
    <p>Rare brews, trusted classics, and suspiciously glowing mystery blends.</p>
  </header>

  <main>
    <section>
      <h2>Available Potions</h2>
      <ul id="potion-list"></ul>
    </section>
  </main>
`;
```

The important line for this page is inside the HTML string:

```html
<ul id="potion-list"></ul>
```

That list is not written directly in `index.html`.

It is created by JavaScript when this line runs:

```js
app.innerHTML = `...`;
```

That means `#potion-list` does not exist right away.

First, the browser loads the page.

Then JavaScript selects `#app`.

Then JavaScript sets `app.innerHTML`.

Only after that does the `<ul id="potion-list"></ul>` exist in the DOM.

So if we want to select that list, we have to do it after the `innerHTML` update.

Order matters here.

Rude, but fair.

## Selecting the Potion List

Now that `app.innerHTML` has created the list, we can select it.

Add this line after the `app.innerHTML` block:

```js
const potionList = document.querySelector("#potion-list");
```

Then inspect it:

```js
console.dir(potionList);
```

Your code should look like this:

```js
const app = document.querySelector("#app");

app.innerHTML = `
  <header>
    <h1>Potion Shelf</h1>
    <p>Rare brews, trusted classics, and suspiciously glowing mystery blends.</p>
  </header>

  <main>
    <section>
      <h2>Available Potions</h2>
      <ul id="potion-list"></ul>
    </section>
  </main>
`;

const potionList = document.querySelector("#potion-list");

console.dir(potionList);
```

Let’s slow that down.

| Code                                     | Meaning                                                    |
| ---------------------------------------- | ---------------------------------------------------------- |
| `const potionList`                       | Create a variable named `potionList`                       |
| `document.querySelector("#potion-list")` | Search the DOM for the element with an id of `potion-list` |
| `"#potion-list"`                         | A CSS selector for the list we created with `innerHTML`    |
| `console.dir(potionList)`                | Inspect the selected list element in the console           |

Refresh the preview and open the console.

You should see the `<ul>` element.

That means JavaScript successfully found the list that it created a moment earlier.

## Now Break It on Purpose

This is one of those bugs that makes way more sense when you see it happen.

Move this line:

```js
const potionList = document.querySelector("#potion-list");
```

above the `app.innerHTML` block.

Your code will look like this temporarily:

```js
const app = document.querySelector("#app");

const potionList = document.querySelector("#potion-list");

app.innerHTML = `
  <header>
    <h1>Potion Shelf</h1>
    <p>Rare brews, trusted classics, and suspiciously glowing mystery blends.</p>
  </header>

  <main>
    <section>
      <h2>Available Potions</h2>
      <ul id="potion-list"></ul>
    </section>
  </main>
`;

console.dir(potionList);
```

Refresh the preview and check the console.

This time, you should see:

```txt
null
```

That is JavaScript saying:

> I looked for `#potion-list`, but I did not find anything.

And JavaScript is right.

When this line ran:

```js
const potionList = document.querySelector("#potion-list");
```

the list had not been created yet.

The list only gets created later, when this line runs:

```js
app.innerHTML = `...`;
```

So JavaScript was not being dramatic.

It searched too early.

There was nothing to find.

## What `null` Means

`null` is a special value that means “nothing is here.”

In this case, it means `querySelector()` did not find a matching element.

That is different from selecting the wrong kind of value.

JavaScript did not find a string.

It did not find an empty list.

It did not find a broken element.

It found nothing.

So it returned `null`.

This is why the order of the code matters.

If we select after the list exists, we get the `<ul>` element.

If we select before the list exists, we get `null`.

## Put It Back in the Right Order

Now move the `potionList` selection back below the `app.innerHTML` block.

The correct order is:

1. Select `#app`.
2. Set `app.innerHTML` to create the app shell.
3. Select `#potion-list`.

Your code should look like this again:

```js
const app = document.querySelector("#app");

app.innerHTML = `
  <header>
    <h1>Potion Shelf</h1>
    <p>Rare brews, trusted classics, and suspiciously glowing mystery blends.</p>
  </header>

  <main>
    <section>
      <h2>Available Potions</h2>
      <ul id="potion-list"></ul>
    </section>
  </main>
`;

const potionList = document.querySelector("#potion-list");

console.dir(potionList);
```

Refresh the preview.

The console should show the `<ul>` element again.

That is the whole lesson.

Create first.

Select after.

## What You Should Notice

This page did not make Potion Shelf look different.

That is okay.

Sometimes the most important code does not change what the user sees right away.

The important change is that JavaScript now has access to the empty list inside the app shell.

First, `app.innerHTML` created the list.

Then `document.querySelector("#potion-list")` selected the list.

That order matters.

If JavaScript tries to select `#potion-list` before `innerHTML` creates it, the result is `null`.

This is the next major DOM idea in the section:

> JavaScript can only select elements that already exist in the DOM.

That may seem obvious once you see it, but this exact mistake causes a lot of bugs.

So now you know what to look for.

If `querySelector()` gives you `null`, one of the first questions to ask is:

> Did this element exist when my selection code ran?

## Technical Vocabulary

| Term             | Meaning                                                                  |
| ---------------- | ------------------------------------------------------------------------ |
| `null`           | A value that means nothing was found or no value exists                  |
| execution order  | The order that code runs in                                              |
| rendered element | An element that has been created and placed into the DOM                 |
| `potionList`     | A variable that stores the selected `<ul id="potion-list"></ul>` element |
| `#potion-list`   | A selector that means “the element with an id of potion-list”            |
| inspect          | To look closely at a value in the console                                |
| temporary code   | Code used briefly to test or inspect something before removing it        |
