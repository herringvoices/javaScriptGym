# Importing Data · Get the Potions

The page has an empty list. Hard-coding potion names directly into HTML would work, but it would tangle the data and the UI together.

> The potion names belong in data. The DOM should display that data.

## Concepts

- Data can live in another module.
- `import` brings exported code into the current file.
- Calling `getPotions()` returns an array.
- Arrays of objects represent structured data.

## Starter Data Shape

```js
const potions = [
  { id: 1, name: "Mender's Sip", baseId: 1, ingredientId: 1 },
  { id: 2, name: "Ember Tonic", baseId: 2, ingredientId: 2 },
  { id: 3, name: "Glacier Draught", baseId: 3, ingredientId: 3 }
];
```

## Code

```js
import { getPotions } from "./database.js";

const potions = getPotions();
console.log(potions);
```

## Keep vs Trash

Keep:

```js
import { getPotions } from "./database.js";
const potions = getPotions();
```

Trash:

```js
console.log(potions);
```

## Technical Vocabulary

| Term | Meaning |
| --- | --- |
| module | A JavaScript file that can import/export code |
| `import` | Bring exported code into the current file |
| array of objects | A list where each item is an object |
| data source | The place the app gets information from |
