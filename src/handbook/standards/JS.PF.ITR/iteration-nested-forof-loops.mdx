# Iteration → Nested for…of Loops (Crossing Collections)

So far, you’ve used loops to:

* visit every hero in the `heroes` array,
* build new arrays like `heroNames`,
* and filter heroes with conditions in a single `for…of` loop.

In the last chapter, you imagined a `for…of` loop as a **conveyor belt** handing you one hero at a time while the machine quietly took care of Start, Stop, and Step.

Now we’ll cross **two** conveyor belts at once: one for heroes, one for their powers.
You’ll handle a **pair** of collections—like heroes and their powers—by nesting one `for…of` loop inside another.

The mental model is still a conveyor belt, just with **two belts**:

* Outer belt: heroes roll past, one hero at a time.
* Inner belt: for each hero, you scan every power in the `powerVault`.

Together, they let you answer questions like:

> “Which powers belong to this hero?”
> “How many powers does each hero have?”

---

## 1) Two belts, one hero at a time

Imagine this structure:

```js
for (const hero of heroes) {
  // hero is one hero object

  for (const power of powerVault) {
    // power is one power object
    // here you can check if this power belongs to this hero
  }
}
```

On each **outer** pass:

* `hero` is one hero from `heroes`.

On each **inner** pass:

* `power` walks through *all* of `powerVault` from start to finish.

Inside the inner loop, you have **both**:

* the current `hero`, and
* the current `power`.

That’s enough to compare fields like `power.heroId === hero.id` and decide whether they go together.

You can think of it as:

> For each hero on the outer belt, run the entire power belt and pick out the powers that match.

## 2) Using nested loops to build summaries

Nested loops aren’t just for logging; they’re also useful for building **summary data**.

For example:

* “How many powers does each hero have?”
* “Can I build a quick lookup list of hero names and their power counts?”

You can answer that by:

1. Looping over each hero,
2. Counting how many powers match that hero inside an inner loop,
3. Pushing a summary object into a new array.

Pattern:

```js
const heroSummaries = [];

for (const hero of heroes) {
  let powerCount = 0;

  for (const power of powerVault) {
    if (power.heroId === hero.id) {
      powerCount = powerCount + 1;
    }
  }

  heroSummaries.push({
    name: hero.name,
    powerCount: powerCount,
  });
}

console.log(heroSummaries);
```

Key ideas:

* `powerCount` is reset to `0` **for each hero** (inside the outer loop).
* The inner loop walks all powers and increments `powerCount` when there’s a match.
* After the inner loop finishes for that hero, you push one summary object.

## 3) Keeping nested loops under control

Nested loops are powerful, but a few habits will keep them understandable:

* Give clear names to your loop variables
  (`hero` / `power`, not `a` / `b`).
* Reset counters or temporary values **inside** the outer loop
  (like `let powerCount = 0;` for each hero).
* Keep most of your work inside the inner loop **small and focused**
  (check a condition, maybe increment a count or push once).

As long as you remember that each hero gets its own full walk through the power vault, nested `for…of` loops stay grounded in the same conveyor belt mental model—just with two belts crossing instead of one.
