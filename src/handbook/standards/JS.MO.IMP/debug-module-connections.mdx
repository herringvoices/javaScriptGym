# Modules → Debug Broken Connections

Before modularization, most of your Census bugs lived inside one file.

Now the project has boundaries between files.

Those boundaries create a new family of mistakes:

- the path points to the wrong module,
- the importing module asks for a name the other module does not export,
- an exported name is misspelled on one side of the connection.

The debugging rhythm you already learned still works:

1. reproduce the problem,
2. read the error,
3. identify the file or import involved,
4. compare what one module provides with what the other module requests,
5. make the smallest repair,
6. run again.

## A path can point to the wrong place

Suppose `catalog.js` correctly imports a `books` array:

```js
import { books } from "./books.js";
```

This version points to a file that does not exist:

```js
import { books } from "./book.js";
```

The exact wording may vary, but the important evidence is the same: JavaScript cannot resolve the module named by that path.

The repair starts by comparing the path after `from` with the actual filename and location in the explorer.

## A named import can request the wrong name

Suppose `inventory.js` provides:

```js
export { countInStock };
```

but `catalog.js` requests:

```js
import { countAvailable } from "./inventory.js";
```

The path is valid, but the two modules disagree about the exported name.

Named imports are contracts between modules. Both sides have to agree on the name.

Use those two comparisons—requested path versus real file, then imported name versus exported name—to create and repair the Census errors in the challenge.

## Use the diagrams as evidence too

When a module connection breaks, your dependency graph can help you remember the intended architecture.

If the graph says:

```text
Main --> Data
```

but the path in `main.js` points to a nonexistent file, the code no longer matches the architecture you intended.

Diagrams do not replace debugging.

They give you another description of what the program is supposed to be.
