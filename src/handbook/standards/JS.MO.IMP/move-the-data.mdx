# Modules → Move the Data

One common way to begin splitting a large file is to move its data into a module of its own.

Imagine a tiny music program that starts like this:

```js
// player.js
const songs = [
  { title: "Static in the Attic", minutes: 3 },
  { title: "Please Hold Forever", minutes: 4 },
];

console.log(`Songs queued: ${songs.length}`);
```

The song records and the code using them have different jobs. We can move the array to `songs.js`.

## Moving code creates a boundary

After the move, the files might temporarily look like this:

```js
// songs.js
const songs = [
  { title: "Static in the Attic", minutes: 3 },
  { title: "Please Hold Forever", minutes: 4 },
];
```

```js
// player.js
console.log(`Songs queued: ${songs.length}`);
```

That program fails. `songs` still exists, but it now belongs to another module. A module does not automatically get access to variables declared in a different file.

Running at this awkward halfway point is useful. The failure proves that the boundary is real.

## Export from the provider

The module that owns a value can make its name available with a **named export**:

```js
// songs.js
const songs = [
  // song objects
];

export { songs };
```

The export does not push `songs` into every file. It says that another module is allowed to request that exact name.

## Import into the consumer

The file that needs the value can request it with a **named import**:

```js
// player.js
import { songs } from "./songs.js";

console.log(`Songs queued: ${songs.length}`);
```

Read the import from left to right:

| Code | Meaning |
| --- | --- |
| `import` | Bring something into this module |
| `{ songs }` | Bring in the named export called `songs` |
| `from` | Specify which module provides it |
| `"./songs.js"` | Start in this folder and load `songs.js` |

The imported name must match the exported name. The path must point to the file that provides it.

## What changed?

The program still has the same data and the same logic.

But responsibility is now split:

```text
data.js   -> owns the cryptid data
main.js   -> uses the data to run the application
```

That means `main.js` now **depends on** `data.js`.
