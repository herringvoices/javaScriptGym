# State & Screen → The Checkbox That Lies

Return the region filter to **All regions**.

Now check **Confirmed only**.

The checkbox changes.

The list does not.

You still see eight records, including the two unconfirmed cryptids.

This time there are at least two possible explanations:

1. the checkbox event never updates the program's state, or
2. the state changes correctly, but the screen is never refreshed.

Those are very different bugs.

Do not guess which one you have.

## Follow the event

The checkbox uses this handler:

```js
confirmedOnly.addEventListener("change", (event) => {
  state.confirmedOnly = event.target.checked;
});
```

Set a breakpoint on the assignment.

Before clicking the checkbox, inspect:

```js
state.confirmedOnly
```

Then click it.

When execution pauses, Step over the assignment and inspect the value again.

If it changes from `false` to `true`, you have proved something useful:

> The event happened, and the state changed.

The bug must be later in the chain.

For this application, the intended flow is:

```text
user action → update state → render → updated screen
```

The region dropdown already follows that flow.
