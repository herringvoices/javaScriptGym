# Console Tracing → Find the Missing Cryptid

The Census Office has eight records.

Six of them say:

```js
confirmed: true
```

But the dashboard reports:

```text
8 records • 5 confirmed • 8 shown
```

There is no error message because nothing JavaScript considers illegal has happened.

The program calculated a number.

It was simply the wrong number.

## Ask the code what it is doing

The summary gets its confirmed count from this function:

```js
function countConfirmed(records) {
  let count = 0;

  for (let i = 0; i < records.length - 1; i++) {
    if (records[i].confirmed) {
      count++;
    }
  }

  return count;
}
```

You could read that function over and over and try to spot the mistake.

Sometimes that works.

A stronger debugging move is to collect evidence about what the loop **actually does**.

A `console.log()` inside a loop can show you each pass as it happens.

For example:

```js
const names = ["Mothman", "Bigfoot", "Nessie"];

for (let i = 0; i < names.length; i++) {
  console.log(i, names[i]);
}
```

produces:

```text
0 Mothman
1 Bigfoot
2 Nessie
```

That log is useful because it answers a specific question:

> Which indexes and values did this loop reach?

Good tracing logs are temporary evidence. They should show the value you are investigating and enough context to know where it came from.

Now you have evidence.

The loop reaches indexes `0` through `6`.

The array also has an item at index `7`.

That last item is Flatwoods Monster, and it is confirmed.

The count is wrong because the loop stops too early.

This is an **off-by-one error**: the loop boundary is one position away from where it should be.

## Wrap up

A useful `console.log()` is not random noise.

You had a question:

> Which records does this loop examine?

Your log answered it.

Next, you will get the same kind of evidence without changing the code at all.
