# Tracing Values → Where Did the Northeast Go?

You know how to pause the Census and inspect a function while it runs.

Now the dashboard gives you a reason to.

Use the **Region** menu and choose **Northeast**.

The source data contains two Northeast records:

- Jersey Devil
- Dover Demon

But the dashboard shows:

```text
8 records • 6 confirmed • 0 shown
```

Nothing crashes.

The filter simply rejects both records.

## Find the decision point

The list comes from:

```js
function getVisibleCryptids() {
  return cryptids.filter(matchesFilters);
}
```

For every cryptid, `filter()` asks `matchesFilters()` whether that record should remain in the visible list.

That makes `matchesFilters()` the useful place to investigate.

Do not start by changing the condition.

Pause there and collect evidence first.

<Callout type="tip" title="Compare the values, not just the line">
  <p className="m-0">
    A condition can look reasonable while comparing the wrong pieces of data. Inspect the object and the state that reach the comparison.
  </p>
</Callout>

<HandbookChallenge
  title="Trace the Northeast filter"
  hints={[

  ]}
  expected={
    <div className="space-y-2">
      <pre className="m-0 whitespace-pre-wrap">{`8 records • 6 confirmed • 2 shown`}</pre>
      <p className="m-0">The visible records are Jersey Devil and Dover Demon.</p>
    </div>
  }
  solution={
    <pre className="m-0 whitespace-pre-wrap">{`const matchesRegion =
  state.region === "all" || cryptid.region === state.region;`}</pre>
  }
>
  <p className="m-0">
    Keep Northeast selected. Set a breakpoint inside <code>matchesFilters()</code> and inspect the records as they pass through.
  </p>
  <p className="m-0">
    Find the first value in the region comparison that does not match the data you expected, fix that access path, then run the program again.
  </p>
</HandbookChallenge>

The important part is not that the typo was `location` instead of `region`.

The useful debugging move was:

1. identify where the decision was made,
2. pause there,
3. inspect both sides of the comparison,
4. find the first unexpected value.

That same move works when the wrong property is buried much deeper than this one.
