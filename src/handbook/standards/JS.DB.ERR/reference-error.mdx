# Error Messages → `ReferenceError`

Run the program again after fixing the `SyntaxError`.

Good news: JavaScript made it far enough to print:

```text
======WEIRD MIKE'S PAWN SHOP======
```

Then it stopped with an error like:

```text
ReferenceError: managerName is not defined
/main.js:47:25
```

So what is this new message telling us? Let's break it down.

The first thing we see is `ReferenceError`. This is the type of error JavaScript found. Unlike the `SyntaxError`, JavaScript understood the file well enough to start running it.

Next we see `managerName is not defined`. JavaScript reached the name `managerName` and tried to find it, but it couldn't.

Finally, `/main.js:47:25` tells you where the program broke: `main.js`, line 47, character 25. That is the line where JavaScript tried to use `managerName`, but it isn't necessarily where the mistake began.

## ReferenceError

A **`ReferenceError`** usually means JavaScript was asked to use a variable or other name it can't find in the current scope.

When you get one, start with the exact name JavaScript printed. Then ask:

- Is the name spelled correctly where it is used?
- Was the variable declared with that exact name?
- Is the declaration in a scope this line can access?
- Is there a similarly named variable nearby?

<Callout type="tip" title="Let the error name your search">
  <p className="m-0">
    If JavaScript says <code>managerName is not defined</code>, start by searching for <code>managerName</code>. Don't scan every function in the file. The error has already narrowed the problem down for you.
  </p>
</Callout>

The line number shows where JavaScript tried—and failed—to find the name. The mistake could be on that line: perhaps the reference was misspelled. Or it could be earlier in the code: perhaps the variable was declared with the wrong name, declared in a different scope, or never declared at all. Compare the name where it is used with the name in its declaration to find which side is wrong.

## Wrap up
A `ReferenceError` is JavaScript saying, roughly:

> **"I understand this code, but I don't know what that name refers to."**

The program now gets through two lines of output.

Then it finds a value, recognizes it perfectly well, and objects to what Mook tries to do with it.
