# Stack Traces → Follow the Call Chain

The first stack frame helped you fix `printDescription()`.

Run the program again.

You should now make it through the description and see:

```text
FEATURED ITEM
```

Then JavaScript stops inside `formatItemName()`.

Your trace should include a chain like:

```text
at formatItemName (main.js:LINE:COLUMN)
at printItem (main.js:LINE:COLUMN)
at printFeaturedItem (main.js:LINE:COLUMN)
at main.js:LINE:COLUMN
```

The first frame shows where JavaScript **noticed** the problem.

But look at the function itself:

```js
function formatItemName(item) {
  return item.name.toUpperCase();
}
```

That code makes sense if `item` is one inventory object with a string `name`.

So the next question is not "How should I rewrite `formatItemName()`?"

It is:

> **What value did the caller give it?**

## Read the stack from the failure backward

Each frame is one active function call.

This stack tells you:

1. `formatItemName()` failed,
2. because `printItem()` called it,
3. `printItem()` was called by `printFeaturedItem()`,
4. and `printFeaturedItem()` was called from the main body of the program.

If the code in the first frame looks correct for the value it expects, move down the stack one frame at a time and inspect the values being passed between functions.
