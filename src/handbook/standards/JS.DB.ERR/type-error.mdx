# Error Messages → `TypeError`

Your program now knows who manages Weird Mike's Pawn Shop. It makes it far enough to print:

```text
======WEIRD MIKE'S PAWN SHOP======
Manager: Mike
```

Then it stops with another error:

```text
TypeError: inventory.length is not a function
/main.js:48:43
```

So what is this message telling us? Let's break it down.

The first thing we see is `TypeError`. This is the type of error JavaScript found. The program is valid JavaScript, and JavaScript found the names it needed. The problem is how the code tries to use one of the values.

Next we see `inventory.length is not a function`. JavaScript found the expression `inventory.length`, but the value it produced wasn't a function. That's our clue about what went wrong.

Finally, `/main.js:48:43` tells you where the program broke: `main.js`, line 48, character 43. That's where JavaScript tried to perform the operation that didn't work.

## TypeError

A **`TypeError`** usually means JavaScript found a value, but the code tried to use it in a way that doesn't work for that kind of value.

When you get a `TypeError`, ask:

- What value or expression does the message name?
- What value did JavaScript actually get?
- What operation did the code try to perform?
- Can that kind of value perform that operation?

## TypeErrors come in different shapes

You don't need to memorize every possible `TypeError` message. Use the same two questions each time: **What value did JavaScript have, and what did the code ask it to do?**

Here are a few common shapes:

### Reading a property from `undefined` or `null`

```js
let user = null;
console.log(user.name);
// TypeError: Cannot read properties of null
```

JavaScript had `null`, and the code asked it to read a `name` property.

### Calling something that is not a function

```js
const config = { start: true };
config();
// TypeError: config is not a function
```

JavaScript had an object, and the code asked it to behave like a function.

### Using a method that the value doesn't have

```js
const itemName = 8;
itemName.toUpperCase();
// TypeError: itemName.toUpperCase is not a function
```

JavaScript had a number, and the code asked it to use a string method.

The messages look different, but the debugging move is the same: identify the value, identify the attempted operation, and compare the two.

## Wrap up

A `TypeError` is JavaScript saying, roughly:

> **"I found the value, but it can't do what this code is asking it to do."**

So far, you have met three useful error categories:

| Error type | Useful first translation |
| --- | --- |
| `SyntaxError` | "I can't understand this code." |
| `ReferenceError` | "I don't know that name." |
| `TypeError` | "I found the value, but it can't be used that way." |

After fixing `inventory.length()`, the program reaches `======INVENTORY======`. Then it hits another `TypeError` inside `formatItemName()`.

We've already been using the file, line, and character beneath each error to find where the program stopped. In the next section, we'll expand the **stack trace** and use its full trail of locations to learn not only where JavaScript failed, but how it got there.
