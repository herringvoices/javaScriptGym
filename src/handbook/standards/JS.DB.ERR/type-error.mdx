# Error Messages → `TypeError`

Your program now knows who manages Weird Mike's Pawn Shop.

Then it reaches this line:

```js
console.log(`Number of Items: ${inventory.length()}`);
```

and reports something like:

```text
TypeError: inventory.length is not a function
```

This time JavaScript successfully found `inventory`.

It successfully found `inventory.length`.

The problem is what the code asks JavaScript to **do with that value**.

A **`TypeError`** happens when JavaScript has a value, but the code tries to use that value in a way that does not work for its type.

The message gives you an important clue:

> `inventory.length` exists, but it is **not a function**.

## TypeErrors come in different shapes

You do not need to memorize every possible `TypeError` message.

The useful habit is to ask:

> **What value did JavaScript actually have, and what operation did the code try to perform on it?**

Here are a few common forms:

### Reading a property from `undefined` or `null`

```js
let user = null;
console.log(user.name);
// TypeError: Cannot read properties of null
```

### Calling something that is not a function

```js
const config = { start: true };
config();
// TypeError: config is not a function
```

### Reassigning a `const`

```js
const maxItems = 100;
maxItems = 200;
// TypeError: Assignment to constant variable.
```

The messages look different, but all three involve a value being used in a way JavaScript cannot perform.

So far, you have met three useful error categories:

| Error type | Useful first translation |
| --- | --- |
| `SyntaxError` | "I cannot understand this code." |
| `ReferenceError` | "I do not know that name." |
| `TypeError` | "I found the value, but it cannot be used that way." |

After fixing `inventory.length()`, you immediately hit another `TypeError`.

This time, we are going to use the information underneath the error message to find it.
