# Stack Traces → Find the Failure

So far, you have mostly cared about the **first line** of an error:

```text
TypeError: item.priceInPennies is not a function
```

But JavaScript usually gives you more information underneath it.

That extra information is the **stack trace**.

For this page, keep your existing inventory and `formatPrice()` function. Replace the inventory loop at the bottom of `main.js` with this version:

```js
function printItem(item) {
  console.log(`${item.name} - ${formatPrice(item.priceInPennies)}`);
  console.log(item.details.trim());
}

console.log("---");
console.log("For Sale:");

for (const item of inventory) {
  printItem(item);
}
```

Run it.

You should get a `TypeError`. Depending on the exact line numbers in your editor, the trace will look something like:

```text
TypeError: Cannot read properties of undefined (reading 'trim')
    at printItem (main.js:LINE:COLUMN)
    at main.js:LINE:COLUMN
```

Your actual line and column numbers are the useful part. Do not worry if they differ from an example.

## A stack frame is one stop in the call history

A line such as:

```text
at printItem (main.js:24:28)
```

is a **stack frame**.

It tells you:

- the function that was running: `printItem`,
- the file: `main.js`,
- the line: `24`,
- and the column: `28`.

When you are debugging your own code, the first frame that points into your readable student file is often the fastest place to start.
