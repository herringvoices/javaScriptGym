# Error Messages → `SyntaxError`

## Welcome to Weird Mike's Pawn Shop

Before we start reading errors, you need something broken to debug.

Welcome to **Weird Mike's Pawn Shop**.

No one's completely sure whether "Weird Mike" describes Mike or the pawn shop. Either way, the inventory is unusual and the software needs work.

Mike had his nephew, **Mook**, put together a program for the shop.

It...doesn't work.

If you open up `main.js` in the editor, you can see poor Mook's faulty code.

<Callout type="danger" title="Important">
  <p className="m-0">
    Don't start fixing things yet. <strong>Run the program first.</strong>
  </p>
</Callout>

<p className="m-0">Mike and Mook are expecting an output like this:</p>

```text
======WEIRD MIKE'S PAWN SHOP======
Manager: Mike
Number of Items: 4
```

<p className="m-0 mt-2">Instead, as you've noticed, they get this:</p>

```bash
SyntaxError: Unexpected identifier 'priceInPennies'
/main.js:7:5
```

So what does this strange, cryptic message mean? Let's peel back the curtain and break it down piece by piece.

The first thing we see is `SyntaxError`.

This is the type of error JavaScript found. We'll talk more about what this error means in a bit.

Next we see `Unexpected identifier 'priceInPennies'`.  This is JavaScript's first clue about what confused it: it found the name `priceInPennies` where it was expecting something else.

Finally, JavaScript tells you where it got stuck: `/main.js:7:5`. This kind of location information is part of what developers call a **stack trace**.

In this case:
- `/main.js` is the file,
- `7` is the line number, and
- `5` is the character position on that line.

We'll learn more about stack traces later on, but for now, the most important piece is the **line number**.

The location doesn't always identify the actual mistake, but it's a good place to start looking.

JavaScript doesn't even make it to the first `console.log()` because it can't get past this problem. It stops before the program can really begin.


## SyntaxError
Before JavaScript can run your code, it first has to **parse** it. That means reading what you wrote and recognizing it as valid JavaScript instructions. The rules for writing valid JavaScript are called **syntax**.

A `SyntaxError` means JavaScript found code that doesn't follow those rules closely enough for it to understand the program.

<Callout type="note" title="JavaScript follows instructions literally">
  <p className="m-0">
    Once JavaScript has parsed the file and starts running it, it generally works from top to bottom, roughly line by line and one statement at a time. We can read ahead, use context clues, and make inferences about what someone meant. JavaScript doesn't. The good news is that JavaScript does exactly what you tell it to. The bad news is that...it does <strong>exactly</strong> what you tell it to.
  </p>
</Callout>

Common causes include:

- a missing `)`, `]`, or `}`,
- a string with a missing quote,
- a missing comma between values or object properties,
- or another piece of malformed JavaScript.

<Callout type="tip" title="Read before you edit">
  <p className="m-0">
    The error points to a location near the place where JavaScript couldn't continue. That location is evidence. Start there instead of scanning the entire file at random.
  </p>
</Callout>

In Weird Mike's inventory, compare the first item object with the objects underneath it. They use the same shape, but one is missing a small piece of punctuation.

## Wrap up
A `SyntaxError` is JavaScript saying, roughly:

> **"I can't understand this code well enough to run it."**

After your fix, the shop heading appears!

...right before JavaScript stops again...

Congratulations on fixing your first bug!
